# 远仓打包机：原版一致性验收

## 本次修复

- 复制 Create 打包机的方块属性，并明确禁用完整方块遮光，避免空心机架内部被按实心方块遮暗。
- 保留 Create 的模型父级、透明通道和机械细节，只替换外框配色。
- Create 6.0.10 的 `PackagerRenderer.getTrayModel` 只将注册的原版打包机识别为普通托盘，其他方块会落入重打包机托盘分支。客户端 Mixin 仅为 `RemotePackagerBlock` 返回 `PACKAGER_TRAY_REGULAR`；其他方块不受影响。
- 普通渲染器与 Flywheel visual 共用这个选择方法，因此两条路径都使用原版网状托盘。没有复制或改写动画曲线、周期、声音、舱门选择或运动方向。
- 方块实体仍继承 Create 的打包、拆包、红石及物流请求行为。发送完成后转换包裹物品类型，保留组件；跨服订单另附既有路由信息。

## 自动检查与边界

`./gradlew build` 包含模型父级、透明通道与 Create 托盘选择入口的静态检查。编译与静态检查不能替代客户端实际加载 Mixin、渲染及物流交互测试。

## 游戏内验收（待执行）

在备份后的测试存档中，将 Create 原版打包机与远仓打包机并排放置，使用相同照明、容器内容和朝向：

1. 未供电、供电、链接三种状态：底部网状托盘可见，机架内部不再异常漆黑，外框保持远仓配色。
2. 六个放置方向逐一检查；相邻实心方块不能让整个空心机架变黑。
3. 对相同库存触发一次红石打包，比较舱门、托盘运动、声音和结束时机；远仓侧只输出远仓包裹。
4. 使用仓储链接器下单，检查地址、内容、多包订单信息及既有跨服路由均保留。
5. 输入普通包裹及远仓包裹，比较拆包动画与库存结果；容器满、输出堵塞、连续订单时不得丢物或复制物品。
6. 分别启用和关闭 Flywheel 后重载客户端，重复托盘、打包、拆包检查。
7. 动画中退出并重进存档，检查包裹、队列与动画恢复；确认原版打包机及重打包机外观未受影响。
