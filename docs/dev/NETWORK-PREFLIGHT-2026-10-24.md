# 0.3.58 上线前复盘

0.3.57 修复目录公告和邀请码找回后，进一步运行实际命令及异步加入回包处理。

## 复现及修复

- 旧存档显式 Legacy 仓库，本地加入成功、跨服加入被错误拒绝。新增回包测试在修复前失败，修复后成功迁移到正式网络。
- 加入回包与现有正式成员关系冲突时，旧实现先写入副本再拒绝，留下虚假的已知网络。现在先检查关系，再写入。
- 加入等待从 10 秒改为 60 秒，使用单调时钟，避免系统校时影响超时计算；超时明确提示检查邀请码、权威节点及队列，不再断言邀请码不存在。
- 记录发起请求时的手持终端。等待期间换成另一台终端或加入其他网络，旧回包不能覆盖它。
- SavedData 的重复回包检查也移到游戏线程；调度或处理异常会完成 Future，使传输层能够重试，不再遗留一直等待的回调。

## 验证结果与边界

- 修复前新增回包回归测试复现 2 项失败：Legacy 拒绝、失败残留。
- 修复后 295 项游戏测试通过，覆盖实际邀请码命令的创建者校验、空网络公告接收、15 秒排队回包、61 秒过期回包、重复回包、换终端和原有成员关系保护。
- 这些是隔离世界中的命令与消息处理测试，不是 ES2/VL4 线上多玩家压力测试。真实 Router、队列积压、模组组合及生产存档仍需现场检查。
- 原有完整构建的 Ponder 验证会报告 diagnostics NBT 与生成脚本不一致；只读比对确认 diagnostics/cache 的 NBT 内容存在差异。本次不改写这些教程资源。

## 更新与现场验收

1. 正常停服后备份存档与 `transerver/`，两服替换为 0.3.58 DistantStock，保留节点身份及配置；不需要升级 Router 或 Transerver。
2. 两服启动后确认 `/transerver status` 已连接；等待节点握手、目录公告和旧队列处理。
3. VL4 创建者执行 `/distantstock network code`；ES2 执行 `/distantstock network` 确认目录，再手持空终端执行 `/distantstock network join-terminal 邀请码`，等待明确的加入成功反馈。
4. 用少量物品验证现有跨服仓库查询和实际收货，再恢复批量业务。命令沿用管理员权限；普通玩家仍使用终端界面。

没有改动存档格式、客户端载荷注册版本或加入协议格式；新增提示包含服务端 fallback，旧客户端没有新翻译键时也能阅读错误信息。这里不构成对任意旧客户端/模组组合的兼容承诺。
