### 1. 谐振飞行胸甲（提交 `069562e`）

**需求**：谐振石英胸甲获得鞘翅飞行能力，类似彩虹化合物的动力鞘翅，空格加速，专用翅膀贴图。

**实现方案**：
- 借用 Create 的 `AllDataComponents.BACKTANK_AIR` 存储压缩空气（无需注册新 DataComponent）
- 覆写 `canElytraFly(ItemStack, LivingEntity)` 和 `elytraFlightTick(ItemStack, LivingEntity, int)` 实现飞行
- 气量懒填充：`inventoryTick` 检测到 `BACKTANK_AIR` 为空时自动充满（`BacktankUtil.maxAir(stack)` 读取 Create 服务端配置，尊重容量附魔）
- 创造模式持续补充气量
- 滑翔时按空格冲刺：`EtherFlightClient` 监听 `ClientTickEvent.Post`，当 `isFallFlying()` 且跳跃键按下时发送 `EtherBoostC2S` 到服务端
- 服务端验证后沿视线方向施加对称冲量（`+0.5 lookAngle`），消耗 10 单位气量
- 专用翅膀渲染：`EtherWingLayer` 继承 `RenderLayer<AbstractClientPlayer, PlayerModel<AbstractClientPlayer>>`，从 `EntityRenderersEvent.AddLayers` 注册到 `PlayerRenderer`，复用 `ModelLayers.ELYTRA` 几何，渲染 `ether_casing_wings.png`（64×32），翅膀随隐身相位淡出
- 气量表显示：覆写 `isBarVisible` / `getBarWidth` / `getBarColor`，调用 `BacktankUtil` API（蓝色条 `0x5FAFDF`）
- 贴图生成：扩展 `scripts/gen_ether_armor.py`，用 V5 机壳面板规则绘制翅膀（左翼 texOffs(22,0) 10×20×2，右翼镜像）

**关键 API**：
- `IItemExtension.canElytraFly(ItemStack, LivingEntity)` — 覆写后 `LocalPlayer.aiStep` 的 jump-to-glide 分支自动生效
- `IItemExtension.elytraFlightTick(ItemStack, LivingEntity, int)` — 每 tick 调用，返回 `false` 时退出飞行
- `BacktankUtil.getAir(stack)` / `consumeAir(entity, stack, amount)` / `maxAir(stack)` — 无 item-class 检查，任何物品都能存气
- `Inventory.tick()` — 遍历 `compartments = ImmutableList.of(items, armor, offhand)`，对每个槽调用 `ItemStack.inventoryTick`，所以盔甲槽每 tick 触发
- `LivingEntityRenderer.addLayer(RenderLayer)` — 附加自定义渲染层
- `EntityRenderersEvent.AddLayers` — mod-bus 事件，`getSkins()` 返回 `SLIM` / `WIDE`，`getSkin(model)` 返回对应 `PlayerRenderer`

**陷阱**：
- `LivingEntity.updateFallFlying()` 是 `private`，无法直接覆写；原版只读 shared flag 7 并调用 `canElytraFly` + `elytraFlightTick`，所以覆写这两个方法足够
- `LocalPlayer.aiStep` 的 creative-flight 分支（1171–1229）无法复用，因为它 gated on `isControlledCamera()`；滑翔加速必须走 C2S payload
- `LocalPlayer.tick()` 只在 `isPassenger()` 时发送 `ServerboundPlayerInputPacket`（携带 `jumping`），服务端永远看不到滑翔玩家的跳跃输入，所以必须自己发 payload
- `BacktankUtil.maxAir(ItemStack)` 读取 `AllConfigs.server().equipment.airInBacktank` + 容量附魔等级，这是**服务端配置**，客户端/物品注册时无法读取，必须在 `inventoryTick` 懒填充
- `ElytraLayer.shouldRender` 是 identity 检查 `Items.ELYTRA`，所以 mixin `ElytraLayer` 无效，必须写独立的 `RenderLayer`
- `PlayerRenderer` 在 `net.minecraft.client.renderer.entity.player` 包，不是 `net.minecraft.client.renderer.entity`

**网络协议版本**：从 `"19"` 升至 `"20"`（在 `ModNet.java` 的 `PayloadRegistrar r = e.registrar("20")`）

**新增文件**：

### 2. 隐身阴影淡出（提交 `05be5b0`）

**需求**：穿戴全套远仓护甲潜行时，脚底椭圆阴影应随着隐身相位淡出，而不是在第一帧就消失。

**实现方案**：
- Mixin `EntityRenderer.getShadowRadius`，在 `@At("HEAD")` 拦截
- 检测实体是否是玩家 + `EtherCasingCloakState.get(player)` 返回的相位 > 0
- 计算 `remaining = 1.0F - (float) phase / PHASES`（PHASES = 12）
- 返回 `shadowRadius * remaining`
- 实体调度器在半径 ≤ 0 时跳过阴影渲染，所以阴影在 12 tick 内线性淡出

**关键 API**：
- `EntityRenderer.getShadowRadius()` — 返回值被实体调度器用于绘制地面椭圆阴影
- `EtherCasingCloakState.get(LivingEntity)` / `get(UUID)` — 返回当前隐身相位（0–12）

**陷阱**：
- 取消 `RenderPlayerEvent.Pre` 只隐藏玩家模型，不隐藏阴影——阴影是实体调度器在 renderer 外部画的
- `EntityRenderer.shadowRadius` 是 protected field，而 `getShadowRadius()` 是可 mixin 的方法

**新增文件**：
- `src/main/java/dev/distantstock/mixin/client/EntityRendererShadowMixin.java`

**Mixin 注册**：已在 `src/main/resources/distantstock.mixins.json` 的 `"client"` 数组中注册为 `"client.EntityRendererShadowMixin"`。

### 3. 网络扬声器去重（提交 `6d6e08b`，合并 PR #5 后的 follow-up）

**需求**：同一频道的多个广播器被同一个拉杆同时触发时，每个玩家只应收到一次消息，而不是每个广播器发一次。

**实现方案**：
- `NetworkBroadcastBus.send` 新增去重守卫：
  - `private record Dispatch(ResourceKey<Level> dimension, long gameTime, UUID network, String text, int soundProfile)`
  - `private static final Set<Dispatch> SENT = new HashSet<>()`
  - `private static long lastTick = Long.MIN_VALUE`
  - 每次 `send` 检测 `level.getGameTime() != lastTick` 时清空 `SENT`
  - 用 `SENT.add(new Dispatch(...))` 判断是否重复，重复则 early-return 0
- 去重范围：**同一 tick 内、同一维度、同一网络、相同文本和音效**的广播只发送一次
- 跨 tick 的重复消息（拉杆关闭再开启）仍然正常发送

**陷阱**：
- `selectNearest` 只能阻止一次 dispatch 通过两个重叠扬声器送达同一玩家两次，但无法跨 dispatch 去重——需要上层守卫
- 去重 key 必须包含 `gameTime`，否则合法的重复广播（拉杆再次拨动）会被永久屏蔽
- `SENT` 只在 tick 推进时清空，所以内存占用始终 ≤ 一个 tick 内的 dispatch 数量（通常个位数）

**修改文件**：
- `src/main/java/dev/distantstock/block/NetworkBroadcastBus.java`

**验证任务**：`verifyNetworkBroadcast`（JavaExec → `dev.distantstock.block.NetworkBroadcastBusCheck`）通过。
