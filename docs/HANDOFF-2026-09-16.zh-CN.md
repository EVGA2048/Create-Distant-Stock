## 二、怎么跑（先做这个，别跳过）

```bash
./gradlew clean build verifyWireCodec verifyParcelOwnership verifyClientAssets
./gradlew -PwithGameTests runGameTestServer      # 服务端 gametest，74 项
./gradlew -PwithGameTests runClientSmoke         # 真实客户端烘焙资源 + 图集断言
```

**判据（重要）**：`runGameTestServer` 在**游戏启动就崩**的情况下也可能报 `BUILD SUCCESSFUL`。
唯一可信的判据是日志里的这两行：

```
N GAME TESTS COMPLETE
required tests failed        ← 出现这行就是有失败，后面列用例名
```

日志在 `build/gametest-run/logs/latest.log`。**不要用 grep 过滤 gradle 的 stdout 判断成败。**
`runGameTestServer` 每次会先删 `build/gametest-run/world` —— 测试世界是会跨次污染的（踩过两次）。

产物：`build/Create-Distant-Stock-<版本>+mc1.21.1.jar`（**没有** `build/libs/`）。

装机（两个实例都要装）：

```bash
# 覆盖前必须确认游戏已退出
ps -eo command | grep -c '[n]et.minecraft.client'     # 必须是 0

python3 scripts/install_client.py build/Create-Distant-Stock-*.jar \
    ~/Documents/minecraft_launcher/.minecraft/mods/

    ~/Documents/minecraft_launcher/.minecraft/versions/ES2_Firmament_1.21.1_9th_9.3.2_SunlightSignal/mods/
```

## 五、架构速查

| 子系统 | 关键类 | 说明 |
|---|---|---|
| 远仓港 | `block/DockBlock(+Entity)` | 一个包裹槽；`automation` 可被传送带插入；底面是回退面；破坏必须 spill |
| 港组 | `routing/DockGroup`、`DockGroupDirectory` | `SavedData`；**权限判定位只有 `admits`，全仓四处调用** |
| 地址投递 | `block/LoadedDocks.importFor` | 按 `PackageItem.matchAddress`；港没写地址＝`*`（谁都收） |
| 包裹托管 | `link/ParcelEscrow(+Pump)`、`ParcelLedger` | 先落盘再投递；投不出去留 HELD，从不丢 |
| 互通塔 | `block/TowerCoreBlockEntity`、`routing/TowerTier`、`TowerActivation` | 7 级（耦合器 5/7/9/11/13/15/17）；并查集合并相交范围；门禁在 `TowerActivation.active` |
| 区块加载 | `block/TowerChunkLoader` | NeoForge `TicketController`，`GRACE_TICKS = 400` |
| 远仓仪表 | `routing/RemoteGaugeOrders`、`block/RemoteOrderSlot`、`RemoteOrderBook` | **一单在途**、`TIMEOUT_TICKS = 20*120`、单次封顶 `remoteGauge.orderStacks` |

| 跨服传输 | `link/TranserverBridge`、`OrderService` | 见第九节 |

**下单逻辑分两层，别写第三份**：`RemoteOrderSlot`（一格）← `RemoteOrderBook`（一块板四格）；

## 六、踩过的坑（会重复踩的）

### 1. `AbstractPanelBehaviour.getFilter()` 故意返回 `EMPTY`
Deployer 的基类这么写是给「根本没有过滤器」的面板类型用的。子类写
`return super.getFilter()` 就会**拿到那个 EMPTY**：面板看着正常、读数照走，
**只是永远看不到过滤物品**——仪表永远不下单，灯根本不是灯。正确读法是 Create 的字段
`filter.item()`。这个 bug 在远仓仪表上活了一整轮才被灯引出来。
同类还有 `getBulbState()` 默认 `DISABLED`。

### 2. Create 的 `getStateForPlacement` 按**方块身份**写死
`FactoryPanelBlock.getStateForPlacement` 里那段「同块放原地 → 改成 `be.addPanel`」是
`state.is(AllBlocks.FACTORY_GAUGE)` 判的。我们的板子不是那块方块，于是退回普通放置，
**板子连同方块实体会被换掉**（数据丢失）。修法在 `GaugePlacementEvents`：
认「任何方块是 `FactoryPanelBlock` 的物品」，撞上我们的板子时把这一下转交给
`state.useItemOn(...)`。`PanelBoardGameTests` 两条盯着它。

### 3. 存档 NBT 布局不许改形状
`RemoteOrderBook.write/read` 的 `RemoteBindings` / `RemoteOutstanding` 是**已经存在世界里的格式**。
读的时候要兼容缺字段的老文件（`getUUID` 缺键返回 **null**，`putUUID(key, null)` 会 **NPE**）。

### 4. 空白和 `*` 的语义
港的地址为空 ＝ `*` ＝ **谁都收**。只给一个港写地址、另一个留空，两个港都会匹配 ——
写测试断言时必须让每个港都写死且不同，否则用例是绿的但什么都证明不了。

### 5. gametest 的其它坑
- 测试世界跨次污染（已在 build.gradle 里删）；
- **一座正在转的塔会关掉它范围外的所有远仓设备**——留下塔的测试会毒死别的用例；
- 有塔在跑时 `survey` 返回 `Snapshot.EMPTY`；
- 塔要 ≥30 rpm（创造马达默认 16 不够，设 64）；
- 事件型 handler 必须用 `SignalLampPanelItem.panelUnder()` / `getTargetedSlot` 把点击解析回格子
  （空格子没有碰撞箱，点击落在板子后面的墙上）。

### 6. 客户端
- **PartialModel 必须在烘焙前注册**（`registerModels()` 那招），否则烘成紫黑缺失模型；
- 其它目录的贴图必须显式列进 `assets/minecraft/atlases/blocks.json`（namespace 必须是 `minecraft`）；
- 改完客户端代码**一定跑 `runClientSmoke`**——今天就是它抓出「模型表搬家后冒烟测试还在反射旧字段」。

### 7. Create API 事实（反汇编确认，别再猜）
- `FactoryPanelBlock` **没有** `createTickerHelper`；覆写 `getTicker` 要自己带 `SmartBlockEntityTicker`。
- `FactoryPanelBlockEntity` **没有** `addToGoggleTooltip`，护目镜要自己 `implements IHaveGoggleInformation`。
- `SmartBlockEntity.attachBehaviourLate(...)` 是 public；`FactoryPanelBlockEntity` 的
  `redraw` / `lastShape` / `panels` 都是 public 字段。
- `PackageItem` 写地址是 **`addAddress(stack, str)`**（不是 `setAddress`）。
- **Create 6.0.10 没有面板类型扩展点**：`FactoryPanelBehaviour.getTypeForSlot` 是 static、
  对槽位 ordinal 做 `tableswitch`，用途是存档还原槽位。自定义面板要落到 Create 的板子上，
  只有 deployer 一条路（见 `docs/design/PANEL-COMPAT-PROPOSAL.zh-CN.md`）。
