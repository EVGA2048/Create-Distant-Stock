# 请求器解绑与信号灯双放置：保守修订

## 使用方式

- 便携式远仓请求器：潜行对空气右键，清除频率、远程网络身份、接收港组；保留地址和其他自定义数据。随后重新选择网络。
- 信号灯：普通右键放居中灯，直接响应红石。潜行右键墙面放四分格灯。拿灯右键已有未占用的仪表格可添加灯。
- 四分格灯通过仪表连接取信号，不直接读取墙后红石。配置好仪表过滤物品后，在仪表中选择“添加新连接”，空手点击同墙面、同朝向、16 格以内的四分格灯。
- 灯接收仪表满足条件/红石强制满足的状态；多输入按任一亮则亮处理。不会把信号灯当成配方原料。

## 保护边界

- 不迁移居中灯和现有存档，不重新生成贴图。
- 已有连线的原版/远仓仪表板暂时拒绝就地转换成混合灯板，避免丢失连接的数量、路径等设置；可在旁边放新的四分格灯再连接。未连接的仪表板可转换，已占用格不会覆盖。
- 依赖两个窄范围 Mixin：客户端允许不同方块类型但相同墙面/朝向的仪表与灯连接；服务端将灯端连接改为信号输入并重新验证距离、容量和方向。原版仪表之间的连接不修改。
- 远仓仪表目前仍只有原版基础行为，跨服生产功能未接入。

## 2026-09-14 续作与验证

- 修正四分格放置在游戏运行时创建临时 BlockItem 的问题。现在通过已有物品的 `getPlacementState` 选择模型，保留原版碰撞和放置检查，不触碰冻结的物品注册表。
- 四分格灯的 PartialModel 提前在客户端初始化时注册。真实客户端检查曾检测到模型缺失，提前注册后首次模型烘焙通过。
- 补齐远仓仪表外壳绘制：原版只为自己的工厂仪表注册静态面板模型，远仓仪表现在复用原版面板组件绘制外壳。
- 客户端灯连接入口不再处理集成服务端事件；添加灯的事件在其他处理器之后执行，并检查玩家放置权限。

验证环境：Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10、Flywheel 1.0.6。

`./gradlew build`：编译、资源检查、解绑数据回归、包裹几何回归均通过。

`./gradlew -PwithGameTests runGameTestServer`：独立测试世界运行后自动退出，两个测试通过。实际验证居中/四分格放置、只消耗一个灯、不多生成仪表、命名保留、副手解绑后重绑、地址保留、工厂仪表与远仓仪表的信号方向、点亮/熄灭、重复连接及断开。服务端 Mixin 在真实模组环境中运行。

`./gradlew -PwithGameTests runClientSmoke`：独立测试客户端烘焙真实资源并自动退出，不打开存档。验证 144 个居中灯状态、20 个四分格灯模型、工厂仪表面板无缺失纹理，以及客户端连线 Mixin 已加载。

这些测试源文件和空测试结构仅在 `-PwithGameTests` 时编入，不进入正常发行 jar。尚未自动验证玩家手动打开仪表 GUI 的全流程、光影整合包、旧存档重载和多人不同权限插件；相关视觉与交互反馈仍需在用户整合包内复核。
