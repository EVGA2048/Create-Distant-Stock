# 远仓思索场景重制

## 展示约定

采用 Create 的小型结构、分步显现、操作提示、关键帧及指向说明。每段围绕一个操作或可见结果；说明之间留出停顿，字幕不重叠。结构与脚本坐标同时维护，场景只展示教学状态，不依赖真实跨服服务。

普通场景使用 7×7 底板；锁链场景使用 9×9 底板。互通塔按高度缩小视图。壁挂设备安装在明确的支撑墙上，蛙港下方使用箱子，旋转运输设备通过边界传动轴与竖直齿轮箱接入动力，不展示创造马达。互通塔西侧接口连接实际流体管道，供液泵位于场景外。

| 结构 | 教学顺序 |
|---|---|
| export | 货源容器与打包机 → 输出漏斗与传送带 → 发送模式 → 侧面输入 → 底部回退提取 |
| import | 接收模式与地址 → 下方溜槽和箱子 → 本地运输与拆包 |
| tune | 手持远仓港右键已有网络 → 放置并保留绑定 → 对应本地仓库 → 空手右键配置 → 固定请求台 |
| status | 待机 → 传输 → 回退堵塞 → 监视器排查 → 修复后扳手清除故障 |
| replenish | 本地监测网络 → 物品与目标数量 → 每格远端货源绑定 → 接收地址 → 拆包入库 |
| redstone | 绑定货源 → 配置订单 → 上升沿触发一次 → 接收与提取 |
| tower | 底部动力 → 八块机壳塔基 → 五段连续耦合器 → 谐振器 → 扳手开启流体口 → 运行条件 → 红石观察窗 |
| diagnostics | 普通目的地地址 → 诊断蛙港日志网络 → 锁链连接与支撑 → Ping 探测 → 无目的地与拥堵的区别 |
| cache | 有效目的地堵塞 → 缓存蛙港 → 查看与取出 → 恢复后重发 |
| logger | 网络范围 → 装纸 → 打开列表 → 确认消音 → 打印 → 修复故障 |
| alarms | 选择工况灯 → 放置链接器 → 分色输入 → 独立红石声光报警器 |

## 对旧场景的纠正

- 输出漏斗与传送带上下对齐；输入漏斗背面实际连接远仓港。
- 漏斗输出接容器，不向传送带方块的物品能力接口注入包裹。
- 发送港的底部提取通道不再被底板封死。
- 消除同坐标重复放置；不再将齿轮与承重方块叠在同一格。
- 锁链连接双向对应，蛙港在锁链下方、支撑箱子上方。
- 远仓仪表显式设置壁挂朝向，并初始化可见的活动仪表格。
- 日志台空手右键只打开列表；确认与打印由界面操作执行。
- 工况灯必须通过链接器接收输入，声光报警器有独立红石输入；不暗示它们自动跟随日志台。
- 中英文说明保持逐段对应；不沿用旧版“直接右键确认”“所有流体接口默认开放”等操作。

## 验证

`python3 scripts/gen_ponder_structures.py` 重建结构。

`./gradlew verifyPonderScenes` 检查结构可重现、坐标范围、重复占位、漏斗和容器对接、锁链双向连接、蛙港支撑及字幕对应关系。该检查已加入 `check`。

`./gradlew runClientSmoke -PwithGameTests` 的 `PonderSceneSmoke` 在实际客户端注册表中检查方块与属性、思索注册、结构读取及字幕资源。该测试不打开存档，不执行依赖已加载世界的完整 Ponder 时间轴。它不能代替游戏内逐帧检查镜头、方块实体动画和字幕遮挡。

所有报警展示均不主动播放音效。

发送演示复用 Create 打包机的完整打包周期及远仓港原有的包裹上浮、缩小吸收渲染。虚拟港的动画进度由思索时间轴控制，恢复结构时清除；实际世界的传输计时保持原样。
