# 远仓信号塔控制器

**Distant Stock Signal Tower Controller**，建议注册名 `distantstock:signal_tower_controller`，尚未注册。

本目录只有离线模型、模拟灯态与接口契约。没有服务端控制、游戏 GUI、区块加载或限速实现；没有改动正式 `src/`、物流或资源，也没有安装到游戏。完整塔仍由基座与塔顶构成，控制器是可独立放置的可选配置入口，**不是第三个必需结构件**。

## 模型与图片

- 一格方块，模型像素边界 `x/z -8..8，y 0..16`，正面朝北。完整机壳，两端铸石盖，短机械面板、棱面旋钮、短拨柄、半透明绑定灯。
- 大面积外壳直接使用 `create_materials.material()` 读取的 Create 安山机壳；安山岩、抛光安山岩与工业铁用于基座、盖板和机械件。蓝灰只作涂装，霁青只作小灯点缀。没有自画均匀灰色柜体，也没有未来电子屏。
- 来源是本机 Create jar，可通过 `CREATE_JAR` 指定。材质变换记录在 `concept.json`，保留原始纹理像素、裁片和颜色变换。原始小装饰仅灯罩与旋钮指针。衍生纹理只供本地概念预览，发布前应另审纹理授权。
- `models/*.mesh.json` 是 `render_scene` 的离线面列表，**不是**游戏可加载的 block JSON。
- 推荐整体图：`build/art/concepts/tower-controller-overview.png`。
- 推荐灯态图：`build/art/concepts/tower-controller-states.png`。
- 单独角度图：同前缀 `front.png`、`back.png`、`side.png`；单独灯态图：`unbound.png`、`bound.png`、`out_of_range.png`、`fault.png`。

所有图片使用英文标签，明确标注离线概念。透视是正交预览，没有调用游戏。生成器验证三个镜头、三组画幅下的全部模型点都在安全边距内，不裁切模型或覆盖标签。

## 供组合场景读取的 API

模块：`scripts/concepts/gen_tower_controller.py`。

- `build(state='bound')` 返回 `list[face]`；允许 `unbound / bound / out_of_range / fault`。
- `textures()` 返回 `dict[str, PIL.Image]`，包含四种灯态使用的纹理。
- 每个面包含 `group / material / points / uv`，并含 `kind` 和 `owner_cell`。材质和分组都使用 `tower_controller/` 前缀，合并塔模型时不会覆盖对方同名材质。
- 模块可由概念脚本目录导入，不执行写盘；使用 `render_scene.move()` 平移或旋转整个模型。旋钮不是运行时输入或动画。
- 灯态只改变绑定灯材质，几何、旋钮、拨柄位置不变；拨柄不表示互通开关实际开关状态。

## 绑定与更新契约

完整机器可读版本见 `control-contract.json`。这是未来实现要求，不是现有通信协议。

1. 一个控制器最多绑定一个完整塔；多个控制器可以绑定同一塔。推荐塔标识使用**服务端生成 UUID + dimension + basePos**，同一位置重建必须产生新 UUID，控制器不静默接管。
2. 配置保存在**塔基座**，控制器只保存绑定身份。客户端快照不是第二份权威配置；每次提交带 `expectedRevision`，服务端原子校验并更新，冲突拒绝覆盖。只有最终生效才递增 revision 并返回成功。
3. 绑定、读快照和提交均检查控制器、操作者权限、同维度、塔 UUID 与位置、完整结构、有效范围和加载状态。范围数值、距离算法均待定，由服务端定义，不能由客户端指定。
4. 位置信息只是候选，不能直接信任。先检查目标区块已加载再读取世界，不为寻找、检查或配置远塔自动加载区块。未加载返回不可用；旧快照不能证明塔仍完整。
5. 每次设备更新重新检查设备身份、位置、维度、类型、操作者权限、本塔受管关系与范围。目标被替换、移动或转管后拒绝旧操作。
6. 更新中的未知字段、能力与设备类型均拒绝。按设备类型定义服务端功能白名单，客户端只能选择其中已有项，不能自己提交任意权限名。

## 控制范围

- **互通开关**：塔级布尔配置，提议默认关闭；尚未接入物流。
- **区块加载开关和选区**：默认关闭，选择单位为 chunk 坐标，不是方块或半径字符串。受服务端总体/玩家/单塔预算、塔能力和允许区域共同限制，数值待定。去重并限制请求体大小，整份选择原子验证，预算预留和未来 ticket 实际应用成功后才确认。失败不部分启用、不亮成功灯，回收本次新增 ticket。关闭、拆塔或塔失效时释放该塔未来 ticket；重启前重新验证。拆控制器不等于拆塔，也不会抹去基座配置。
- **传输限速**：单位暂建议“包裹/秒”，明确待定；不是 HTTP bytes 限速。数值、零值、突发和方向语义待定，本轮没有执行或限速逻辑。
- **逐设备白名单和功能开关**：条目包含 `identity + pos + dimension + type`。默认白名单为空；只允许本塔受管且有效范围内的设备。能力来自服务端类型白名单。

当前源码核对的示例：

- `DockBlockEntity.java`：有包裹库存和导入/导出模式；可以讨论 `parcel_import / parcel_export` 两个候选功能，但现有代码没有塔控制门禁。
- `GaugeBlockEntity.java`：有频率、地址、库存缓存和上次订单显示；仅列 `stock_status_read` 候选，其余需完整调用链核对。
- `MonitorBlockEntity.java`：有本地/对端运行指标、积压和连接状态；列 `link_status_read` 候选。
- `RequesterItem.java`：是手持请求器物品，使用时打开已有请求菜单，**不是放置方块**。它的身份、持有者和当前位置校验待设计，当前不把它伪装成具有固定 pos 的受管方块，候选功能留空。

以上能力名全部是接口提案，不是已注册能力。已有请求器菜单不能证明控制器也有游戏 GUI。

## 模拟状态

- `unbound`：未绑定，控制不可用。
- `bound`：绑定有效，霁青半透明灯；仅代表绑定，不代表互通或区块加载开启。
- `out_of_range`：保留绑定身份但禁止配置，琥珀灯。
- `fault`：塔被替换、不完整、权限失效、未加载或应用失败等情况的概念归类，红灯并应返回具体原因。失败不伪装成功；未来 GUI 应单独显示区块加载实际状态。

灯态优先级与更细错误展示仍可进一步设计。没有注册未命名流体，没有为概念虚构 fluid ID。

## 复现与验证

在仓库根目录使用现有 Python 环境：

- `python3 -B scripts/concepts/gen_tower_controller.py`：生成契约、四份面网格、纹理和九张预览图，再验证。
- 再执行一次同一命令：验证重复生成结果。
- `python3 -B scripts/concepts/gen_tower_controller.py --check`：只读检查，不创建目录或写文件；逐个比较保存的 JSON、纹理和重新渲染像素，检查完整面属性、有限坐标、单格边界、非退化面、材质来源、灯罩透明度、状态几何一致性和镜头安全边距。

依赖现有 Pillow、NumPy 和本机 Create jar；脚本不安装依赖，也不会调用共享脚本的生成入口。输出严格限制到本目录和 `build/art/concepts/tower-controller-*`。本轮验证是美术和契约一致性检查，不是服务端安全实现测试或游戏兼容性测试。
