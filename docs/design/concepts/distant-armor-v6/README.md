# 远仓机壳护甲 V6 · 让以太显形

概念稿。**未接入模组**，`src/main` 一个字节都没改。

---

## 一、为什么要有 V6

V5 定下的是**造型纪律**，而且定得很对：护甲不发明新造型，当作「用远仓机壳方块拼出来的」；轮廓与钻石甲 alpha 逐字节一致；全身只留一处装饰。V1→V2「越简单越对」、V3/V4 两次加内容被 V5 收回，这条教训值得继续守。

但 V5 有一件事没说：**材质**。

这套甲叫「谐振**石英**」，配方是 10× 磨制以太石英 + 2× 以太构件 + 1× 远仓机壳，包在**下界合金**底子上；而它的每一条能力都是拿**介质**换的（介质挡耐久、介质驱动速度与抗性）。可穿上它，**看不到一点石英，也看不到一点介质**——通体石板灰，读起来像混凝土。

同时，护腿和靴子到现在**没有任何独有能力，也没有造型语言**，是四件里最没存在感的两件。

V6 要解决的就是这两条，其它一律不动。

---

## 二、三个方向

三个方案都保持 V5 纪律：机壳边框、alpha 逐字节不变、不引入新配色、不发光的。区别只在**让多少以太露出来**。

### A · 介质脉络

通体仍是机壳。介质作为**一条连续通道**从领口进、经胸前的液位镜、从腹甲出，并沿手臂外侧与小腿正面贯通到靴口。

- 全身上下大约二十来个以太像素，是三个方案里最克制的。
- 关键在**连续**。第一版把通道拆成几段、每段循环换色，结果每格底色的明度又各不相同，读成了虚线加理发店转筒。通道必须是一根不断的、单色的线，才读得出「管路」而不是「贴花」。

### B · 石英嵌板

每个甲面的中心整块换成以太石英嵌板，机壳退成边框。整件甲变成灰框蓝晶。

- 材质最强，但**丢了机壳身份**——它读起来是「另一套甲」，不是「机壳甲上镶了石英」。
- 四像素宽的甲面（手臂、腿）去掉两边框只剩两像素嵌板，再按明度 ramp 上色就变成条形码，只能用平色；用了平色又变成大块死蓝。
- **判断：这条路我不推荐。**

### C · 仪器与工作层 ★

上半身与下半身分工：

| | 材质 | 理由 |
|---|---|---|
| 头盔 | 机壳 + 石英嵌板 | 独有能力：内置工程护目镜 |
| 胸甲 | 机壳 + 石英嵌板 + 胸前液位镜 | 独有能力：介质驱动飞行 |
| 手臂 | 机壳 + 通道 | 通道从胸口引向双手 |
| 护腿 | 机壳 + 通道 + 膝甲 | **下半身第一次有了自己的语言** |
| 靴子 | 机壳 | 通道在靴口收住 |

- 承载石英的两件，正好是**两件真正有独有能力的**。造型跟着功能走，不是平均分配。
- 下半身靠通道和膝甲拿到身份，而不是靠加东西。
- **推荐这一版。**

## 三、一条新提议：把介质做成看得见的

三个方案都把胸口那枚 2×2 小窗放大成了一枚**竖长条液位镜**（深槽 + 浅蓝液面）。既然已经是液位镜，就顺便让它真的当液位镜用：

**用现成的相位贴图机制，把介质余量做成四档贴图。**

护甲已经有一套 13 张相位贴图的管线（`_phase_0..12`，现在只给隐身用），机制是「服务端在状态翻转时发一次 `CloakStateS2C`，客户端自己推动画」。介质余量是**每件一个数**，挂在同一套管线上：服务端按 1/3、2/3 两个阈值各发一次包，客户端换贴图。液位镜里的液面随之升降。

这样「介质抵消耐久消耗」这件事**在模型上直接看得见**，不需要任何文字提示，也不需要 HUD 之外的读法。

> 注意与现有 HUD 条的关系：`EtherCasingArmorItem` 已经把 reserve 画成物品耐久条了（以太青绿 `#6ED2C8` / 熔融紫水晶紫 `#B56CFF`）。液位镜是同一信息的**模型内表达**，两者应当保持同一个口径，不要各算各的。介质颜色也可以顺带带进液面——但这会让贴图分叉成两套（青绿/紫），要不要做需要先定。

## 四、守住的规则

1. **alpha 与 `diamond_layer_{1,2}` 逐字节一致**——`build_art.py` 里有断言，改动轮廓会直接炸。实装只需要换贴图，不涉及模型。
2. **不新增配色**。石英色阶取自以太石英物品本身；机壳色阶原样沿用 V5。石英的整体重量压在机壳中心（明度 195–223）**之下**，最亮一档停在与机壳中心同重的位置，所以它不会亮过自己的框、不会读成发光。
3. **分离靠彩度，不靠明度**。第一版把石英做得灰扑扑，怕它「发光」；结果是整件甲糊成灰蓝一片，读起来只是「V5 换了蓝色」。机壳中心与浅蓝灰落在同一个明度带上，只有彩度能把它们分开——这条是这次最重要的一条教训。
4. **不出现药水粒子**。已核实：现有护甲代码里**一处 `MobEffect` 都没有**，速度 / 伤害 / 减伤全部走 `AttributeModifier`（`EtherCasingMediumServer:32-35`），属性修改器本身不产生粒子。**新增任何能力都必须走同一路线**，不要图省事用 `MobEffectInstance`——那会立刻带出药水漩涡粒子。
5. 立体附件（V4 路线）仍然不做——实装端没有渲染管线支持，只有贴图路线被接受过。
