# 双块信号链路概念

当前方案是玩家分别放置的**一格底座 + 一格塔顶**，中间为空气和霁青蓝白光柱。没有整塔注册方块，没有实体光柱方块。旧大型机架方案已废弃。

## 重建与接口

在 DistantStock 根执行 `python3 -B scripts/concepts/gen_tower.py`。使用当前已有 Pillow、NumPy 和共用 `render_scene.py`；不安装、不修改正式 `src`。

动画/主线程接口：`build(phase=0, gap=3, powered=True, link_state='enabled', chunk_state='enabled') -> (mesh, components)`。`phase` 为 0..1 闭合循环，底部服务表针随其往返；`gap` 为两实体块之间的空气格数，正整数；`powered=False` 完全移除 `beam` 特效组。两颗底座灯通过 `link_state` 和 `chunk_state` 独立控制，状态为 `off`、`enabled` 或 `fault`。

- 底座：X/Z -8..8，Y 0..16。
- 塔顶：X/Z -8..8，Y `16*(gap+1)..16*(gap+2)`。
- 总高 `gap+2` 格，仅两个实体组件。
- 光柱主柱半宽 1.5 模型像素，蓝白色；外层半宽 3，霁青低 alpha。无粒子。
- 每颗灯泡包含粗铁灯座、短颈、半透明玻璃球壳和实体内芯，固定占据底座正面上半区。
- 左灯是基本互通：启用蓝色，关闭白色，故障橙黄色。
- 右灯是区块加载：启用霁青色，关闭白色，故障橙黄色。
- 灯泡外壳保持固定体量，状态只改变颜色、透明度和内芯发光，不随状态缩小。

搭建顺序：先放底座并连接输入，在光柱旁搭临时脚手架，放置正上方塔顶，拆除脚手架。中间始终为空气，不注册 beam 方块。

## 造型和功能边界

底座是粗安山岩与白灰铸件，正面改为左右双灯仓：每颗灯都由粗铁底座、短颈、半透明玻璃球壳和明显的实体发光芯组成。基本互通灯位于左侧，区块加载灯位于右侧；两灯保持独立间距和固定大体量。关闭状态显示白色内芯，故障状态优先显示橙黄色。下方只保留低位机械服务表，仪表不再承担主要识别作用。

动力接口在南面中心 `(0,8,8)`，采用真正方形轴端和方形轴承；流体口在东面中心 `(8,8,0)`，两者按标准方块面的中心对齐。底座顶部仍保留凹入式中央发射口，塔顶保留完整一格的外壳体量、短白灰凸筋和顶部霁青玻璃芯；不做现代小屏、窄灯条或密集按钮。没有黄色主色、大飞轮或环架。

建议等级公式为 `effectiveTier = min(heightTier, rpmTier)`。高度映射需封顶，转速映射限制有效等级；具体阈值、上限均未确定。2/4/6 格仅供视觉比较，不是已定玩法。

指针表计划显示以太储量，塔顶灯计划右键查看链路状态和故障。**当前仅布局/模型验证；结构识别、等级、交互和运行逻辑均尚未实现**，JSON 中相应字段均为 `implemented:false`。

机器入口 `concept.json`；离线网格 `mesh.json`，不是原生 Minecraft 方块 JSON。`validation.json` 记录 108 组间距/动画/供电组合、两块本地边界、光柱关闭与循环闭合、PNG 格式验证。
