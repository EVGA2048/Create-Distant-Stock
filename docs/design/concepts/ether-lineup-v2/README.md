# 以太设备线 V2 · 外观重设计概念

V2 是对 V1 的重做。V1（`../ether-lineup-v1/`）被否掉的原因是：造型自己发明得太多、贴图是我自己画的渐变、以太部分过于发光科幻。V2 改成两条硬规则：

1. **只在现有模型上小改**——每个设备的元素都是在现有模型 JSON 上追加，原有形状、尺寸、UV 一律不动。
2. **只用现有贴图**——方块贴图全部引用 `distantstock:` / `create:` 里已经存在的文件，一个新方块贴图都没有画。

统一的母题只有一个，取自互通塔核心本身：**黄铜底座托一块以太晶体**。所有新增元素都在重复这个母题（桅杆顶端的节点、谐振器的顶冠、时钟的同步节点），没有引入新形状语言。

## 各设备改了什么

| 设备 | 改动 |
|---|---|
| 远仓请求台（`gauge`） | 128px 的天线贴图元素换成黄铜桅杆 + 以太晶体节点；钢梁立柱正面开一扇黄铜框以太观察窗。 |
| 互通塔耦合器（上/下） | 以太柱中段加一圈黄铜箍，四根角柱同高处加黄铜卡箍。 |
| 以太谐振器 | 待机时也显示耦合器同款以太玻璃柱；顶部换成核心同款黄铜座 + 以太晶块。运行时的光束保持原样。 |
| 远仓日志台 | 打印机下方加黄铜框以太链路窗，打印机顶加黄铜压条，其余不动。 |
| 辉光管时钟 | 工业铁框换成互通塔的浅色外壳，上下黄铜压边，冒号管上方加以太同步节点；数字与辉光管贴图不变。 |
| 翻牌时钟 | 直接用 Create 翻牌显示器的正面贴图，配远仓浅色外壳、黄铜压边和以太同步节点。该方块已从代码中移除，恢复需要重新实现方块与渲染器。 |

`models/` 是可直接参考的方块模型 JSON。`renders/` 是单独的渲染图。`textures/` 只有两个文件，就是晶体图标的两个方案。

## 说明

- 翻牌时钟已在本轮修复中从代码里移除，这里的方案要落地需要重新实现方块和渲染器。
- 晶体图标不透明、不发光、无光晕，颜色**全部**取自现有以太石英与以太构件的色阶（`#507b9b #35536e #8dbbd6 #699dbc #b6d8e8 #d9ebee #f3f6e9 #293f53 #d7aa5e #9e6947 #724731 #b57849`），没有引入任何新色。高级感来自更大的晶体和明确的黄铜镶嵌，而不是发光。
- 晶体的合成定位只是建议，未实装：以太构件 + 黄铜块，在运行中的以太谐振器上序列组装。
- 已用数值方式检查（图像未经目视检查，请以实际观感为准）：
  - 每个新增元素的贴图引用都能解析到 `distantstock:` 或 `create:` 里已存在的文件，方块部分零个 `concept:` 引用。
  - 所有渲染的画面包围盒都在画布内且非空。
  - 新旧渲染逐像素对比，每个设备都有可见改动（改动像素数 3569 ~ 23082）。
  - 晶体图标的不透明像素数：A 118、B 122，高于磨制以太石英的 113，低于以太构件的 151。
  - 两个晶体图标的色板都完全落在现有色阶之内（差集为空）。
- 没有修改 `src/main/resources` 下的任何正式资源，也没有改动代码。

## 复现

```sh
cd docs/design/concepts/ether-lineup-v2
python3 -B build_devices.py && python3 -B build_crystal.py
```

依赖 `scripts/concepts/` 下的渲染器和 Create 6.0.10 jar（可用 `CREATE_JAR` 指定路径），以及 `build/moddev/artifacts` 里的原版资源 jar。`build_devices.py` 的翻牌时钟对比图会用 `git show HEAD:` 读取已移除的旧模型，所以要在 Git 仓库里跑。
