# 从零开始：把包裹发到对面

这份是**玩家视角**的教程：两台服务器从零开始，怎么把一单货从 B 送到 A。
每一步后面括起来的是"这一步在代码里是什么"，方便对着实现核对。

**约定**：A = 下单的那一侧（你要收货的地方），B = 有货的那一侧（仓库）。

---

## 〇、两台服务器都要先有

1. **两侧都装**：Create + 本模组（Distant Stock）+ Transerver，并且都连上同一个 Router。
   （`[Distant Stock] attached to Transerver node <uuid>` 出现在日志里就是连上了。）
2. **两侧各建一座互通塔**，并且**转起来**（底座底面接传动轴，转速够）。
   —— 塔是硬门槛：**远仓打包机不在任何一座正在运行的塔的范围内，就完全不打包**
   （`RemotePackagerBlockEntity.attemptToSend` 第一句就是 `TowerActivation.active`）。
   塔的等级决定它能带载多少台设备（港/请求台/仪表/打包机都算设备）。
3. 打开监视器或戴护目镜看一眼塔的读数，确认不是「未接通应力」。

> 为什么必须要有塔：塔是"这条货走不走得出去"的开关，也是扣以太的地方。

---

## 一、B 端（仓库侧）要搭的东西

| 东西 | 干什么 | 怎么搭 |
|---|---|---|
| **Create 物流网络** | 有库存、能被打包机取货 | 箱子/库存链接/工厂仪表那套，随便你 |
| **远仓打包机** | **只有它**打的包才是"远仓包裹"，才带路由 | 贴着要出货的箱子放，和普通打包机一样接入网络 |
| **远仓港** | 包裹从这里过关 | 放在传送带能送到的地方；**用扳手对着它按住右键**把模式设成「出货」或「双向」（出厂默认是**收货**） |
| **传送带 / 溜槽 / 漏斗** | 把打包机出来的包裹送进远仓港 | 打包机 → 港 |

**关键点**：包裹出打包机以后**没有任何自动寻路**，得靠你把实体物流接到港里。
（Q1 的抱怨就是这个：不接就被玩家骂。）

**远仓港挂在哪个组**：手持终端，在终端里选好「接收港组」，**潜行右键**港 → 港就挂到那个组上。
港的收件条件**只有这一个**：发给这个组的包裹一定落进组里某一个港（按优先级挑空闲的）。
包裹身上写的地址跟"港收不收"无关 —— 它落地**之后**才起作用（见第五点五节）。

---

## 二、配对（只有一件事需要它）

要让 A 认识 **B 的港组**（比如你想"货送到 B 的某个人手上，留在 B"），需要配对码：

1. **B 端**：`/distantstock pair create <组名>` → 得到一个码（10 分钟、一次性）。
2. **A 端**：`/distantstock pair redeem <码>` → A 的终端列表里出现 `远仓B · 组名`。

**如果货是要回到你自己这边，这一步可以跳过** —— 你选自己的组就行（见下）。
对面的**物流网络**不需要配对码：每台服务器每 45 秒公告一次自己的网络，A 的终端列表里
本来就能看到（带 `远仓B` 前缀）。

---

## 三、A 端（下单侧）要搭的东西

- **一张 Create 物流网络**（终端要绑到它上面，或绑到对面的网络）。
- **一个远仓港**，放在你方便取货的地方。这是货最终落地的港。
- 或者：**远仓请求台 / 工厂仪表上的远仓仪表**（自动化补货用，见第五节）。

### 把 A 的港配置好：手持终端 + 潜行右键那个港

这一下只写一样东西：**接收港组** = 终端上「接收港组」那个框里的组。
动作栏会报出写进去的是哪个组；组是锁着的而你不是组主/成员 → 拒绝，并说明为什么。

戴护目镜看那个港，第一行下面就是「接收港组：X（本组 N 个港）」—— 港挂在哪个组、这个组里有几个港，
一眼看得到。一个组里有几个港是有区别的：只有一个港＝没有冗余，几个港＝按优先级挑空闲的那个。

---

## 四、下单：终端上四个框怎么填

在 A 的终端里（手持终端右键，或请求台右键）：

| 框 | 填什么 | 说明 |
|---|---|---|
| **网络**（列表里选） | **B 的那张网络** | 列表里带 `远仓B` 前缀，来自公告 |
| **接收港组** | **你自己的组**（或者你想要的、A 上的组） | 见下面那段 |
| **远端地址**（底下的框） | **包裹在 B 上被认领时**要写的地址 | 如果你想用蛙港把包裹从 B 的网络上拿走，就填那个蛙港的地址 |
| **本端地址**（港组上面那格） | **货落到 A 的港以后**要改成的地址 | 填 A 这边接它的蛙港/分拣点的地址；留空＝过海后不改地址 |

然后 **Shift+Enter**（或点发送）下单。

### 「接收港组」到底决定什么

同一个下拉框，两种含义，看那个组属于谁：

- **选你自己的组**（A 目录里的）→ **货回到 A**，从这个组的港出来。
  B 那边看到这个组名它不认识 → 判定"寄回下单节点"
  （`TranserverOrderService.destinationNode`）。
- **选配对码引进来的、属于 B 的组** → **货留在 B**，从 B 那个组的港出来。
  这就是"从别人的仓库买东西，直接送给站在仓库旁边的朋友"。

> 这一条是目前最不直观的地方，见文末「还不合理的地方」。

## 五、自动化补货（可选）

不想每次手动下单，有两条自动路：

- **远仓红石请求器**：给红石脉冲就下单。**物品清单和送货地址都用它自己屏幕上那套 Create 原版界面**，
  「网络 + 接收港组」来自绑定时你手里那台终端（**调谐好的终端右键它**；潜行右键解绑）。
  没绑定时它护目镜上会写明"现在是一台普通红石请求器"，按脉冲走本机网络 —— 不会装作在工作。
  它没有本端地址框，所以过海后不改地址。
- **工厂仪表上的远仓仪表**：一格仪表盯一种物品，低于目标就补一单，
  同一时刻只允许一单在途。地址在它自己的界面里填。

---

## 五点五、地址到底管什么

**港不看地址** —— 它只看接收港组（见第三节）。地址是**包裹身上**的东西，它管的是落地**之后**：
包裹从港里出来以后，由本机物流（蛙港、溜槽、传送带）按它继续分拣。所以一条完整的路线是这样的：

```
B 打包时写「远端地址」 → 过海时换成「本端地址」 → 落进 A 的港（只看组）
                                                  → 传送带/蛙港取走 → 按它身上的地址去最终那一点
```

这也就是为什么「本端地址」值得填：它是**落地之后**的分拣地址，不是港的收件条件。

匹配规则仍然是 **Create 原版的规矩**，我们一个字符都没另立：`*` 是文本通配符，而且**两边都可以是
模式** —— 蛙港地址写 `工厂/*` 能接地址为 `工厂/铁锭` 的包裹，反过来也一样。蛙港地址栏上那句
「使用 * 作为文本通配符」就是这件事。这条规矩现在由蛙港（Create 自己的机器）执行，我们不再插手。

我们只加了一层：**`@名字` = 指名给某个玩家**（写法借自无人机物流的运输蜂停泊港，那边是
"地址写玩家名，停泊港把包裹送到那个人手上"）。它的意思是两件具体的事：

- 包裹落地以后**只有那个人能把它从港里拿走**。别人空手右键会被拒绝，并被告知「这是给 X 的包裹」。
- 那个人在线时，包裹落地会收到一句「你的包裹到了：坐标」。

名字查不到档（离线、改名、从没见过）时按名字本身不区分大小写地比 —— 一件指名给人的包裹不该因为
服务器查不到档就谁也拿不走，那是把货锁死，比给错人更糟。

**用法**：想给谁寄东西，就把他加进一个港组（他会收到/他能在下单时选到），下单时地址写
`@他的名字`，货就只有他能取。给自己的港也一样：挂一个只属于你的组，地址写 `@你自己`。

---

## 六、货到了之后

- A 的港**空手右键**取出包裹（收到货、或者卡住的包裹都这么拿）。
- 包裹在手里**摸一下**能看到两个地址：
  - Create 自己那行 = 它现在身上写的地址；
  - 紫的一行 = `跨服寄往 <服务器> · <组名>`；
  - 青的一行 = `过海后改用地址：X`（如果填了本端地址）。
  过海那一刻换成 X，标签清掉，所以**落地以后只剩一个地址**。
- 港上面的灯：熄灭＝没接入，绿＝待机，青闪＝发送中，橙闪＝回退堵塞，红＝故障。
  卡住时戴护目镜看港，会说清楚卡在哪一条（没有组 / 没有路由 / 塔付不起以太）。

---

## 七、从零开始的最短路径（只有两台服、什么都没有）

```
B 端：
  1. 建塔（底座 + 耦合器 + 谐振器），底面接轴转起来
  2. 箱子 → 库存链接/网络
  3. 远仓打包机贴着箱子放，接入同一张网络（必须在塔范围内）
  4. 远仓港放在旁边，扳手右键设成「双向」
  5. 传送带：打包机 → 远仓港
  6. （可选）终端里选好「接收港组」，潜行右键港把它挂上去
A 端：
  7. 建塔，转起来
  8. 远仓港放在手边，扳手右键设成「双向」或「收货」
  9. 终端里：接收港组 = 你自己建一个组（随便起名，回车就建了）
  10. 潜行右键 A 的港 → 动作栏报出它进了哪个组
  11. 终端：网络选 B 那张；接收港组选你自己那个组；
      远端地址 = B 那边认领包裹用的地址（用蛙港就填那个蛙港的地址，传送带直连可以留空）
      本端地址 = 货落地以后改成什么地址（A 这边的蛙港/分拣点地址；不填就不改）
  12. Shift+Enter 下单
  13. 空手右键港取货（要接着分拣就让它身后的传送带/蛙港按地址接手）
```

## 还不合理的地方（一边写一边记下来的）

1. **「接收港组」一个框两种含义**：本地组 = 货回来，远端组 = 货留对面。
   界面上完全看不出这条规则，只能靠"这个组名是不是我这边建的"来判断。
2. **远仓打包机不在塔范围内时，下单方完全看不到原因**：A 那边显示"已下单"，
   B 这边什么都不发生（不打包、不报错、不留痕）。
3. **两种接线方式对"远端地址"的要求正好相反**（传送带直连可留空、蛙港按地址取必须填对），
   界面上看不出来 —— 但接线本身是 Create 的机制，不该由我们提示。
4. **两个地址框仍然抽象**：远端地址/本端地址这两个词是从"包裹的视角"起的名，
   站在 A 端看是"对面门牌 / 自己门牌"，得解释一遍才懂。
5. **一个组里的港不再按地址分工**（2026-09-17 定案）：想按地址分流就得一个地址一个组，
   或者靠落地之后的蛙港去分。组多了列表会长。
6. **配对码只在"货留对面"时才需要**，但界面和列表里没有说明，玩家容易以为必须先配对。
8. **以太不足就滞留**（`tower.chargeParcels` 开着时）：A 下单时看不到，货卡在 B 的港里。
