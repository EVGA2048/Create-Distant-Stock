# 2026-09-16 接盘修复记录

本记录补充 `HANDOFF-2026-09-16.zh-CN.md`，不替代其中的架构及环境说明。
本轮聚焦请求器配送链和 Transerver 的回执故障，没有修改美术、权限方案或世界互通塔。

## 已定位并修复

### 1. 本地下单丢失收货港组

带服务器上下文的 `OrderService.place` 原先在本地分支退回无路由请求，选中的收货港组没有写入
`OrderRouteDirectory`。现在本地请求也生成目的节点、港组、订单关联信息，并走现有的有路由打包入口。
没有配置 Transerver 的单机使用已有的本机哨兵节点 ID；明确携带本机 `RemoteNetworkId` 的请求也走本地分支。
旧的无服务器参数入口保持兼容，生产中的请求器和远仓仪表调用服务器参数入口。

### 2. 拆单后只有首个包裹能发出

原实现每托管一个包裹就删除整个 Create orderId 的路由。原版打包机生成的后续包裹不自带远仓路由，
因此滞留发送港。新的测试实际复现：一单 640 个铁锭，修复本地下单后只收到首包的 576 个。

现在按 Create 自带的 linkIndex、fragmentIndex、isFinal、isFinalLink 记录已托管分片，
所有链接的所有分片齐全后才清理路由。记录可以保存、加载，并容忍乱序和重复分片。
进度字段是新增 NBT 字段，旧记录缺少这些字段时按尚未记录进度读取。

同时修复路由表碰撞检查先覆盖、后抛异常的问题：整批预检，再写入。
4096 条未完成订单的上限保留；满表时拒绝新路由并在打包前返回失败，不能静默淘汰仍在途的旧订单。
如果玩家销毁包裹，相关未完成订单会保留；以后需要显式的取消/管理入口，不能按时间盲删。

### 3. Transerver 迟到回执导致持续 pump failed

使用真实本机 HTTP Router 和持久化文件存储复现：

1. 发送方重试 outbox，同时收到第一次终态回执。
2. 应用读取并确认完成结果，删除 `send-results`。
3. 接收方识别重复消息，不重复执行业务，但重发终态回执。
4. 发送方已经没有 outbox 或 send-results，抛出 `Receipt has no matching outgoing message`。

修复在独立仓库 `../Transerver`：新增持久化 `sent-receipts` 记录，与可被应用消费的结果分离。
相同回执在发送方重启后仍可确认，不重新生成应用结果；未知、目标不匹配或内容冲突的回执继续拒绝。
旧版本仍留有 `send-results` 的消息可以补建记录。

注意：如果旧版本已消费结果、又没有留下可验证证据，不能自动推断旧回执可信。
此类历史现场仍需核对发送方、接收方和 Router 记录，不能直接清空队列。
`sent-receipts` 和原有接收端 `completed` 一样暂不自动清理；后续需要协调保留期限，而非单端 TTL。

错误信息现在包含失败阶段及异常原因链，多个阶段失败保留为 suppressed exceptions。
因此 `/transerver status` 不再只显示没有原因的 `pump failed`。
这是已复现的真实漏洞，**尚不能断言它就是 DS 原先两台 Minecraft 服务端现场的唯一原因**。

## 验证证据

- 接盘基线：构建、wire codec、parcel ownership、client assets 检查通过；原有 74 项游戏测试通过。
- 修复后：78 项游戏测试全部通过，读取日志确认了完成标记，而非仅看 Gradle 返回码。
- 新增游戏测试：
  - 请求服务 → 原版 Create 打包机 → 两个包裹 → 发送港 → 托管 → 选定接收港组，640 个铁锭全部送达；
  - 明确的本机 RemoteNetworkId 在没有 Transerver 配置时走通同一条流程；
  - 乱序/重复分片及 NBT 保存加载后正确清理路由；
  - orderId 碰撞不覆盖旧路由，也不留下部分写入。
- 上述端到端测试调用真实请求服务和真实原版打包机；打包机到港之间用物品能力接口模拟输送搬运，
  **不等于点击客户端 UI、真实传送带布局或跨服全过程已经实测**。
- Transerver：29 项测试全部通过，包含三节点 HTTP 互通、迟到回执与发送方重启回归、未知/冲突回执拒绝。
- 真实客户端资源冒烟通过：144 个方块状态、20 个四分格灯模型、6 个远仓仪表模型，
  30 张图集纹理、6 场 Ponder，以及工厂仪表和客户端 mixin 检查通过。
- `runGameTestServer` 新增完成标记和日志时间检查，防止启动早退或陈旧日志造成假绿。
