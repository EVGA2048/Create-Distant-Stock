# 监控与日志

远仓把“状态”和“事件”分成两套设备。

- **远仓监视器**：回答“现在系统是什么状态”；
- **远仓日志台**：回答“发生过什么、哪些故障还没确认”。

大型工厂建议两种都放。

---

## 远仓监视器

监视器适合常驻控制室。

它显示当前链路、节点、仓储网络和互通塔等实时状态。

手持已经绑定网络的便携式远仓终端右键监视器，可以指定它重点监控的仓储网络。

空手右键打开界面。

管理员潜行打开监视器时，可以进入服务器侧配置页面。

### 适合看什么

出现以下问题时，先看监视器：

- 对面服务器是否在线；
- Transerver 是否已经接入；
- 当前选中的仓储网络是否存在；
- 互通塔是否运行；
- 塔是不是过载；
- 有多少设备正在被带载；
- 区块加载范围是否开启。

## 远仓日志台

日志台是事件终端和告警器。

它不是全服广播器。每台日志台在放置前都要先绑定到一张已有的 Create 物流网络。

### 绑定

拿着**日志台物品**，先右键一个已经加入 Create 物流网络的物流链接。

绑定成功后，日志台物品会保存：

- Create 仓储网络；
- 对应远仓网络作用域；
- 当前节点信息。

未绑定的日志台不能直接作为正常设备放置。

---

## 两个辉光管

日志台正面有两个小型辉光管。

字符使用 Create 自己的辉光管字符渲染，可以显示字母和数字。

当前状态码：

| 显示 | 含义 |
| --- | --- |
| `OK` | 没有活动 WARN / ERROR |
| `OF` | 绑定网络离线或当前不可用 |
| `W1`～`W9` | 存在未确认 WARN；数字为当前该级事件数，上限显示 9 |
| `WA` | WARN 已打印确认，但故障仍未恢复 |
| `E1`～`E9` | 存在未确认 ERROR |
| `EA` | ERROR 已打印确认，但故障仍未恢复 |

**确认不等于恢复。**

打印小票以后，日志台停止针对这条事件蜂鸣，但对应灯可以继续保持故障状态，直到系统真正恢复。

---

## 三个灯泡

当前灯语义：

### 绿灯

系统正常工作时常亮。

### 黄灯

存在 WARN 时使用。

- 未确认：闪烁；
- 已打印确认：常亮。

### 红灯

存在 ERROR 时使用。

- 未确认：闪烁；
- 已打印确认：常亮。

### 离线

绑定网络离线时，三灯熄灭，辉光管显示 `OF`。

---

## 蜂鸣器

日志台使用和工况灯相同的工业蜂鸣器音效。

只有未确认的 WARN / ERROR 会响。

- WARN：约每 3 秒提示一次；
- ERROR：约每 1.1 秒一个报警节拍；
- INFO：不响；
- 已经打印确认的事件：不响。

打印对应事件的小票，就是日志台的确认操作。

系统不存在“只消音、不留记录”的独立 ACK。即使旧协议发送确认动作，服务端也会按打印流程处理。

---

## 打印小票

日志台存在未确认 WARN / ERROR 时，右键可以打印当前优先级最高的一条事件。

打印以后：

1. 生成一张 **远仓事件记录**；
2. 事件标记为已确认；
3. 对应蜂鸣停止；
4. 日志台打印口短暂显示纸张；
5. 故障如果还没恢复，灯仍保持对应状态。

小票是普通物品记录，不提供右键 UI。

### 小票内容

Lore 中包含：

- 事件发生时间；
- 打印时间；
- INFO / WARN / ERROR；
- 事件代码；
- 来源类型；
- 来源；
- Create 网络 UUID；
- 远仓网络 UUID；
- 详细信息；
- 重复次数；
- 事件 UUID。

它可以作为工厂事故记录、维护凭证或玩家服务器里的值班记录保留。

### 日志台替换纸卷

日志台使用“日志台替换纸卷”作为打印耗材。

- 新放置的日志台纸量为 `0 / 16`；
- 手持替换纸卷右键空纸日志台，消耗 1 个纸卷并装入 **16 次打印量**；
- 每打印一张事件记录消耗 1；
- 当前纸卷没有用完时不会消耗新的替换纸卷；
- 护目镜和日志界面都会显示剩余纸量。

纸用完以后，日志台仍会照常记录事件、亮告警灯并蜂鸣；但打印按钮不可用。由于“打印 = 确认”，**缺纸时也不能 ACK 或消音**。

## 事件等级

远仓事件目前分为：

### INFO

信息记录。

不触发蜂鸣，也不作为故障灯告警。

### WARN

系统仍可能继续工作，但需要注意。

例如：

- 部分物流链接离线；
- 网络被锁定；
- 包裹暂时堵塞；
- 自动化订单长时间未完成。

### ERROR

当前问题已经足以影响正常物流，或长时间 WARN 已升级。

例如持续卡包、网络不可用等。

---

## 当前会进入日志系统的项目

包括但不限于：

- Transerver 链路异常；
- 互通塔相关异常；
- 包裹隔离；
- 路由无目标；
- 接收地址冲突；
- 远仓港回退面堵塞；
- 远仓港发出舱长时间卡包；
- Create 仓储网络离线；
- 部分物流链接离线；
- Create 网络锁定；
- package promise 长时间未完成。

### 自动化停滞

当前自动化健康检测把长时间未完成的 Create package promise 视作异常：

- 60 秒：WARN；
- 180 秒：升级 ERROR。

### 远仓港卡包

发出舱中的包裹持续无法离开：

- 5 秒：WARN；
- 60 秒：升级 ERROR。

恢复以后，活动事件自动清除。

## 工况灯

日志台负责“自动发现的系统事件”；工况灯负责“你自己定义的现场信号”。

两者适合配合使用。

例如：

```text
日志台
负责：网络、包裹、远仓港、塔、跨服链路

工况灯
负责：产线停机、原料不足、人工呼叫、检修模式
```

工况链接器的四路输入为红、黄、绿和蜂鸣器使能。

三种颜色可以同时点亮。

蜂鸣器使能时：

- 红灯持续亮：按节拍报警；
- 黄灯 0→1：提示一次；
- 绿灯 0→1：提示一次。

需要闪灯时，把 Create **脉冲计时器**放在输入侧；如果单个脉冲太短，再接**脉冲延长器**。

---

## 排障顺序

一条远仓线路不工作时，建议从外到内：

1. 监视器：节点和 Transerver 是否在线；
2. 互通塔：设备是否被带载；
3. 日志台：有没有明确 WARN / ERROR；
4. 远仓港：有没有包裹堵塞、无目标或回退；
5. 来源仓库：订单有没有真正打包；
6. 接收端：接收港地址是否正确，本地出口是否有空间。

不要一边排查一边同时重建两边网络。先找到包裹最后一次确定出现的位置，再从那里往后查。
