# 监控与日志

远仓把“实时状态”和“事件历史”拆成两类设备：

- **远仓监视器**：现在系统运行得怎么样；
- **远仓日志台**：发生过什么、哪些故障还没有真正恢复。

大型工厂建议两种都放。

---

## 远仓监视器

监视器适合常驻中央控制室。

### 两行 Create 翻牌显示

当前物理显示使用 Create 原生 Flap Display。单方块高的 Create 翻牌屏本身就是两行，因此当前正式版本保持两行布局。

监视器每约 100 tick 切换一页：

| 页 | 上行 | 下行 |
| --- | --- | --- |
| TPS | `TPS` | 本服 TPS |
| MSPT | `MSPT` | 本服 MSPT |
| PING | `PING` | 对端 RTT |
| BACK | `BACK` | 订单 + 包裹 backlog |
| PEER | `PEER` | 最近对端 TPS，没有新公布时为 `----` |
| DEV | `DEV` | 当前网络设备数量 |

左灯反映本服 TPS：

- `>= 18 TPS`：绿；
- `>= 12 TPS`：橙；
- `< 12 TPS`：红。

右灯反映链路状态：

- **OFF**：transport 不通或没有可用链路；
- **ONLINE**：链路正常且最近有对端状态；
- **SYNCING**：链路已通，但暂时还没收到新的对端状态；
- **FAULT**：链路存在，但最近操作已经报告失败。

### 完整监控界面

空手右键监视器会打开完整仪表板。当前页面显示：

- 本机 TPS / MSPT；
- 对端 TPS / MSPT；
- RTT；
- 在线节点；
- 订单深度；
- 包裹深度；
- in-flight；
- 失败次数。

互通塔页面还会显示：

- 塔成员；
- 塔等级与覆盖；
- 旋转速度与应力；
- 区块加载半径；
- 以太存量；
- 当前流量。

管理员潜行打开监视器时可以进入服务器侧配置页面。

### 与日志台的关系

当前版本两者**没有直接 UI 联动**。

监视器还不会把 EventRegistry 的 `WARN / ERROR` 自动塞进翻牌显示。它负责实时链路、负载和塔状态；日志台负责事件、确认和历史。

三行翻牌 / 全局告警状态条属于后续设计，不是当前正式玩法。

## 远仓日志台

日志台是事件终端、告警器和纸质记录设备。

它不是全服广播器。每台日志台在放置前要先绑定到一张本地 Create 物流网络。

### 绑定

拿着**日志台物品**右键一个已经加入 Create 物流网络的物流链接。

绑定后的日志台物品会保存本地 Create 网络身份；放置后日志台按这个 scope 过滤事件。

---

## 两个辉光管状态码

字符使用 Create 自己的 Nixie glyph renderer。

当前正式状态码：

| 显示 | 含义 |
| --- | --- |
| `OK` | 网络正常、没有活动 WARN / ERROR，并且纸卷可用 |
| `PE` | Paper Empty；纸量为 0，日志台无法打印/确认下一条告警 |
| `AL` | 存在未确认 WARN |
| `ER` | 存在未确认 ERROR |
| `AC` | 告警已打印确认，但对应 WARN / ERROR 仍未恢复 |
| `--` | 绑定网络当前离线 / 不可用 |

状态优先级上，网络离线和真实告警优先于单纯缺纸；缺纸不会把一个 ERROR 盖成 `PE`。

**确认不等于恢复。**

打印小票以后，对应事件停止蜂鸣，但故障还存在时仍保持告警状态，直到系统真的恢复并清除活动事件。

---

## 灯光

### 绿灯

`OK` 正常工作。

### 黄灯

WARN 状态使用黄灯。

- 未确认 WARN：告警外观；
- 已确认未恢复：确认后的稳定外观；
- `PE` 缺纸也复用 WARN 级黄色提示，因为它已经会阻止下一次打印/ACK。

### 红灯

ERROR 状态使用红灯。

- 未确认：报警外观；
- 已确认未恢复：确认后的稳定红色外观。

### 离线

绑定网络不可用时进入 OFFLINE 外观，辉光管显示 `--`。

---

## 蜂鸣器

日志台使用和工况灯相同的工业蜂鸣器音效。

只有**未确认的活动 WARN / ERROR**会响：

- WARN：约每 3 秒提示一次；
- ERROR：约每 1.1 秒报警一次；
- INFO：不响；
- 已打印确认的事件：不响。

单纯缺纸本身不会制造一个虚假的 EventRegistry WARN 来持续蜂鸣；它通过 `PE` 和黄色状态提示维护人员。

---

## 打印 = ACK

日志台存在未确认 WARN / ERROR 时，空手右键可以打印当前优先级最高的一条事件。

成功打印后：

1. 生成一张**远仓事件记录**；
2. 消耗 1 次纸量；
3. 事件标记为 acknowledged；
4. 对应蜂鸣停止；
5. 打印口短暂显示纸张；
6. 故障未恢复时，日志台继续显示 `AC` 与对应灯态。

系统没有单独的“静音但不留凭证”操作。

### 小票内容

小票 Lore 中包含：

- 事件发生时间；
- 打印时间；
- INFO / WARN / ERROR；
- 事件代码；
- 来源类型与来源；
- Create 网络 UUID；
- 远仓网络 UUID；
- 详细信息；
- 重复次数；
- 事件 UUID。

## 日志台替换纸卷

新放置日志台：

```text
0 / 16
状态：PE
```

手持替换纸卷右键**纸量为 0**的日志台：

```text
消耗 1 卷
→ 装入 16 次打印量
```

每次打印消耗 1。

当前纸卷没用完时不能提前塞第二卷。

纸用完以后：

- 事件仍然照常记录；
- 已经存在的未确认 WARN / ERROR 继续蜂鸣；
- 日志台显示 `PE`，前提是没有更高优先级活动告警；
- 不能打印；
- 因为“打印 = ACK”，所以也不能确认或消音。

装入新纸卷或耗尽最后一张纸时，状态会立即刷新，不需要等下一个 1 秒健康采样周期。

## 事件等级

### INFO

信息记录，不触发告警蜂鸣。

### WARN

系统通常还能继续运行，但需要处理。

例如：

- 部分物流链接离线；
- Create 网络锁定；
- 包裹暂时堵塞；
- 自动化订单长时间未完成。

### ERROR

已经影响正常物流，或某些 WARN 持续过久后升级。

---

## 当前会进入日志系统的项目

包括但不限于：

- Transerver 链路异常；
- 互通塔异常；
- 包裹隔离；
- 路由无目标；
- 接收地址 / 接收港组异常；
- 远仓港回退面堵塞；
- 远仓港发出舱长时间卡包；
- Create 仓储网络离线；
- 部分物流链接离线；
- Create 网络锁定；
- package promise 长时间未完成。

### 自动化停滞

当前健康检测：

- 60 秒：WARN；
- 180 秒：升级 ERROR。

### 远仓港卡包

发出舱持续无法离开：

- 5 秒：WARN；
- 60 秒：升级 ERROR。

恢复以后活动事件自动清除。

## 工况灯

日志台负责“系统自动发现的事件”；工况灯负责“玩家自己定义的现场信号”。

```text
日志台
网络 / 包裹 / 港 / 塔 / Transerver

工况灯
产线停机 / 原料不足 / 人工呼叫 / 检修模式
```

工况链接器四路输入为红、黄、绿和蜂鸣器使能。

- 红 + 蜂鸣器使能：周期报警；
- 黄 0→1：提示一次；
- 绿 0→1：提示一次。

---

## 排障顺序

1. 监视器：节点、Transerver、队列和塔是否正常；
2. 互通塔：设备是否被带载；
3. 日志台：有没有明确 `AL / ER / AC`；
4. 远仓港：有没有堵塞、无接收端或回退；
5. 来源仓库：订单是否真正打包；
6. 接收端：接收港组是否正确、出口是否有空间。

不要同时重建两端配置。先找到包裹最后一次确定出现的位置，再继续往后查。
