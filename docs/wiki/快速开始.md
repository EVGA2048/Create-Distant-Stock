# 快速开始

这一页只做一件事：让两台已经安装远仓的服务器完成第一笔跨服订单。

不讨论高级路由，不讨论多港冗余，也不要求一开始就把整座工厂接进来。

> 以下步骤默认服务器管理员已经把 Transerver 配好，两端可以互相通信。

---

## 1. 两边先各自有一张能工作的 Create 仓储网络

远仓不是仓储系统本身。

来源端至少应有：

- Create 仓储网络；
- 仓储链接；
- 能正常打包订单的本地物流；
- 一台远仓打包机；
- 一台远仓港。

接收端至少应有：

- 一台远仓港；
- 能把包裹从港口继续送走的本地物流。

如果 Create 自己的仓储网络都不能完成本地订单，先把本地系统修好，再接远仓。

---

## 2. 建互通塔

远仓设备不是放下就永久在线。

一座最小的互通塔需要：

1. **互通塔底座**；
2. 底座正下方输入旋转动力；
3. 至少 **5 个互通塔耦合器**连续向上；
4. 最顶端放置 **以太谐振器**。

5 个耦合器是 I 级塔。I 级塔可以带载 8 台远仓设备，设备覆盖半径为 32 格。

底座只从**下方**接受旋转动力。侧面接轴没有作用。

塔建好并正常转动后，再把远仓港、请求设备等放进它的覆盖范围。

详细结构见：[互通塔](互通塔.md)。

---

## 3. 用便携式远仓终端选中本地仓库

手持 **便携式远仓终端**右键打开界面。

先切到本服仓库，选中要接入远仓的 Create 仓储网络。

终端完成绑定后会记住这张网络。它之后也会被用作其它远仓设备的“配置钥匙”。

潜行并对空气右键可以清除终端当前绑定。

---

## 4. 创建或加入远仓网络

在终端的“网络”页面中，把当前本地 Create 仓储网络加入一张正式远仓网络。**这一步是远仓路由的前置条件，不可跳过。**

第一台服务器：

1. 选中本地仓库；
2. 创建远仓网络；
3. 给它起一个名称；
4. 复制加入码。

第二台服务器：

1. 选中本地仓库；
2. 打开“网络”页面；
3. 输入第一台服务器给出的加入码；
4. 等待加入完成。

加入完成后，两边的仓储网络才属于同一个远仓网络。只有从这一步开始，它们才能共享该网络下的接收港地址并建立远程订单。

加入码用于建立成员关系，不是每次启动都要重新填写。创建者重置加入码，也不会把已经加入的成员踢掉。

---

## 5. 在接收端准备一个接收港地址

接收港地址是一组远仓港的逻辑名称，并且**只在当前远仓网络内有效**。另一张远仓网络即使也有一个叫 `Main` 的地址，也与这里的 `Main` 完全不同。

第一条测试线路只需要一个地址，例如：

```text
Main
```

把终端的当前接收港地址切到 `Main`，然后**潜行右键接收端远仓港**。

这一下表示：

> 这个港属于 `Main`，并作为收货港工作。

以后可以把多个远仓港加入同一个地址，组成并行接收组；第一条线路没有必要一开始就这样做。

---

## 6. 配置发送端远仓港

在来源服务器上，终端应选中：

- 要发货的仓储网络；
- 目标服务器可用的接收港地址，例如 `Main`。

手持这个终端**普通右键发送端远仓港**。

这一下表示：

> 这个港负责发送，并把默认目的地指向终端当前选择的接收港地址。

用工程师护目镜查看远仓港时，应能看到它当前绑定的网络、模式、接收港地址和状态。

---

## 7. 接入远仓打包机

远仓打包机负责把来源仓库给出的物品变成远仓运输使用的包裹。

它仍然属于 Create 包裹物流的一部分。不要把它理解成“跨服箱子”。

最简单的检查方法是：先确认来源仓库收到订单后，确实有包裹进入发送端远仓港。

如果包裹根本没有到港，问题还在本地 Create 物流，不在 Transerver。

---

## 8. 从另一端下第一笔订单

现在回到接收服务器。

打开便携式远仓终端：

1. 切到远端仓库；
2. 选择一个确实存在于来源仓库的物品；
3. 选择数量；
4. 选择接收港地址 `Main`；
5. 如有需要，填写包裹地址；
6. 提交订单。

订单成功后，流程应当是：

```text
接收端提交订单
  ↓
来源端 Create 仓库处理订单
  ↓
远仓打包机生成包裹
  ↓
发送端远仓港
  ↓
Transerver
  ↓
接收端 Main 港组
  ↓
本地包裹物流
```

---

## 9. 第一笔测试不要接太复杂

第一次联调建议：

- 只用一张来源仓库；
- 一个接收港地址；
- 两边各一个远仓港；
- 一种普通原版物品；
- 数量 1～16；
- 接收端先让包裹直接落进箱子或简单传送带。

第一笔成功后，再加远仓仪表、红石请求器、多港、多线路和自动补货。

---

## 如果没有成功

按包裹走过的顺序排查，不要一上来同时改两边配置：

1. **终端能否看到远端仓库？**
   - 看不到：先检查远仓网络成员和 Transerver。
2. **来源仓库有没有真的打出包裹？**
   - 没有：检查 Create 仓储网络和打包机。
3. **包裹有没有进入发送港？**
   - 没有：检查本地物流。
4. **发送港是否显示无目的地、堵塞或未激活？**
   - 有：按港口状态处理。
5. **接收港是否在正确的接收港地址内？**
6. **接收港是否有空间把包裹交出来？**
7. **远仓日志台有没有 WARN / ERROR？**

更详细的故障信息见：[监控与日志](监控与日志.md)。
