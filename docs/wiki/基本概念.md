# 基本概念

远仓的机器不少，但真正决定系统怎么工作的，是几类“身份”和“路线”。

理解这些以后，很多配置动作其实都只是把某个设备指向其中一个身份。

---

## Create 仓储网络

这是 Create 自己的仓储网络，也是远仓读取库存和提交订单的基本单位。

远仓不会把它改造成另一种网络。

一张 Create 仓储网络在远仓中仍然有自己独立的：

- 库存；
- 打包设备；
- 本地地址；
- 仓储链接；
- 网络 UUID。

远仓终端所谓“切换仓库”，本质上是在切换当前查看或操作的 Create 仓储网络。

本地 Create 网络的所有权与锁定仍由 Create 自己管理。首次把本地仓库接入远仓、或修改它所属的远仓网络，需要通过 Create 的管理权限；操作已绑定的本地终端/请求台也遵守 Create 的交互权限。

---

## 远仓网络

远仓网络是远仓的**路由命名空间**，也是跨服务器的仓储成员组。

它同时解决两个问题：

> 哪几张 Create 仓储网络应该互相认识？  
> 哪些接收港地址、订单和设备绑定属于同一套路由空间？

例如两台服务器分别有：

```text
ES2        3 张 Create 仓储网络
Parallel   2 张 Create 仓储网络
```

不需要让全部五张仓库彼此可见。可以只把其中两张加入同一个远仓网络。

远仓网络通过长期加入码添加成员。单人存档也可以创建正式远仓网络；只有加入其它节点创建的网络时才需要 Transerver。

**远仓网络的成员是 Create 仓储网络，不是玩家。** 玩家只拥有管理权限。一个玩家可以管理多张远仓网络，但同一张 Create 仓储网络同一时间只能属于一张远仓网络。

设备也不单独“加入”远仓网络。请求台、远仓港、仪表等先绑定一张 Create 仓储网络，再实时读取这张 Create 网络当前所属的远仓网络。因此两台设备即使保存过不同的旧缓存，也不能让同一张 Create 网络同时落进两个远仓网络。

远仓网络不是可选标签。未加入正式远仓网络的仓库不能创建/选择远仓接收地址，也不能发起远程订单。旧存档中的 Legacy 作用域只用于读取兼容数据，不再参与新路由。

接收港地址始终属于一张远仓网络。同名地址可以存在于不同网络中，不会互相冲突或串包。它不负责选择包裹最终从哪个具体港出来；那是该网络中接收港地址自己的工作。

---

## 接收港地址

接收港地址是一组接收远仓包裹的远仓港。

它是跨服路由的目的地。

一个地址可以只有一个港，也可以有多个港：

```text
接收港地址「Factory-A」
├─ 港 1 · 优先级高
├─ 港 2 · 优先级中
└─ 港 3 · 备用
```

包裹发送到 `Factory-A` 时，不需要知道三个港的坐标。远仓会从这组港中选择当前可用的接收端。

这使港口可以维护、扩容或更换，而不用让所有发送端重新记一遍方块位置。

### 默认接收港地址

系统存在一个默认地址，用于未单独分组的港。

它适合测试和简单线路。正式工厂更建议给不同用途的线路建立明确名称，例如：

```text
Raw-Material
Assembly
Warehouse-East
Returns
```

## 包裹地址

包裹地址属于 Create 包裹本身。

它和接收港地址的作用阶段不同：

```text
跨服阶段：接收港地址
落地以后：包裹地址
```

例如：

```text
接收港地址 = Factory-A
包裹地址   = Gear-Line
```

远仓先把包裹送到 `Factory-A` 的某个港。包裹离开远仓港以后，本地 Create 物流再按 `Gear-Line` 继续分拣。

因此，同一个接收港地址可以同时承接很多不同包裹地址。

---

## 本地仓库与远端仓库

“本地”和“远端”都是相对于你当前所在服务器说的。

- **本地仓库**：当前服务器上的 Create 仓储网络；
- **远端仓库**：其它服务器通过远仓网络公布出来的 Create 仓储网络。

便携式远仓终端可以在两者之间切换。

只有本地仓库可以在本服执行创建/加入/退出远仓网络等成员管理操作。远端仓库是只读成员视图。

## 绑定

大多数远仓设备不会自己猜“你想让它连哪张仓库”。

最常见的配置方式是：

1. 先让便携式远仓终端选中目标仓库；
2. 手持这个终端右键设备；
3. 设备复制终端当前的网络和目的地信息。

不同设备会复制不同部分：

- 远仓请求台：货源网络、地址和接收港地址；
- 远仓仪表：远端货源和补货目的地；
- 远仓红石请求器：远端货源和接收港地址；
- 远仓监视器：监控目标网络；
- 远仓港：根据普通右键或潜行右键，设置发送目标或接收港地址。

所以便携式远仓终端除了“下订单”，也是整套系统的配置工具。

## 远仓设备与互通塔

远仓设备的工作范围由互通塔提供。

塔负责：

- 设备覆盖半径；
- 最大带载设备数；
- 区块加载能力；
- 旋转应力消耗；
- 可选的以太运输费用。

塔不是 Transerver 的替代品。

**互通塔是游戏内的机器条件，Transerver 是服务器间的消息传输层。**

一个设备可能处在正常网络连接中，但因为没有被运行中的互通塔覆盖而不工作。

## 包裹不是一次性消息

远仓包裹在跨服过程中有独立身份。

系统会跟踪发送、接收、回执、退件和隔离状态，避免把“HTTP 请求成功”错误地当成“物品已经安全到达”。

几个重要结果：

- 重复收到同一个包裹，不会生成两份物品；
- 目标港暂时没有空间时，可以重试；
- 目标明确拒收时，可以退回；
- 无法正常恢复的内容进入隔离库，而不是直接删掉；
- 原港消失时，退件仍可进入服务器退件箱。

普通玩家通常不需要接触这些内部记录；管理员在故障恢复时会用到。

---

## “离线”和“没有库存”不是一回事

远仓终端和仪表显示的数据来自远端定期公布的仓储状态。

因此：

- 远端网络离线：表示目前不能可靠联系或没有有效公布；
- 库存为 0：表示对方在线，但报告当前没有这种物品；
- 数据暂时未刷新：可能仍允许订单发送，由来源端最终决定能否满足。

不要把三种情况都理解成“远仓坏了”。
