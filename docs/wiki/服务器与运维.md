# 服务器与运维

这一页面向服务器管理员。

普通玩家通常不需要直接操作 Transerver 文件、退件箱或隔离库。

---

## 运行要求

当前开发目标：

- Minecraft 1.21.1；
- NeoForge 21.1.x；
- Create 6.0.x；
- Transerver 0.1.x；
- Java 21。

参与远仓互通的 Minecraft 服务器都需要安装 Distant Stock、Create 和 Transerver。

客户端也需要安装 Distant Stock 和 Create，才能正确加载模型、界面、Ponder 和客户端逻辑。

---

## Transerver

当前默认 transport 模式是：

```toml
transport.mode = "transerver"
```

Transerver 提供：

- 节点身份；
- 持久消息；
- 重试；
- 回执；
- 去重；
- Router 转发。

远仓自己的包裹系统在其上继续维护包裹托管与物品安全状态。

### 节点身份

每台 Minecraft 服务器都有 Transerver 节点身份文件：

```text
transerver/node-identity.properties
```

不要把它当缓存随手删掉。

节点身份与 Router/secret/transport 状态分离：即使 Transerver 的跨服传输被禁用或启动失败，`node-identity.properties` 仍会被加载并向 Distant Stock 提供稳定 UUID。传输离线只表示不能跨节点发消息，不表示“本机没有身份”。

删除后会生成新的节点 UUID，旧网络、路由和其它服务器记住的节点身份不会自动变成新 UUID。

迁移服务器目录时，应把这个文件和世界数据一起备份。

## 远仓配置

Distant Stock 的服务器配置位于：

```text
config/distantstock-common.toml
```

当前仍保留一部分 legacy transport 配置，用于迁移或兼容旧部署。正常新部署优先使用 Transerver。

玩家玩法相关的主要配置包括：

### 机壳红石传播

```toml
casing.redstoneRange = 32
```

控制相连远仓机壳观察窗状态传播的最大距离。

### 互通塔包裹计费

```toml
tower.chargeParcels = true
tower.parcelCost = 250
```

默认每个离开受塔带载远仓港的包裹消耗 250 mB 以太。

### 区块选择总上限

```toml
tower.maxSelectedChunks = 512
```

限制各塔通过监视器选择的区块加载范围总量。

### 塔待机费用

```toml
tower.standbyCost = 0
```

默认关闭。

### 远仓仪表单次订单量

```toml
remoteGauge.orderStacks = 1
```

控制单个远仓仪表一次最多补多少组物品。

## 管理命令

远仓主命令：

```text
/distantstock
```

常用诊断：

```text
/distantstock status
/distantstock tower
/distantstock stock
```

### 远仓网络

```text
/distantstock network list
/distantstock network create <名称>
/distantstock network code
/distantstock network reset-code
/distantstock network join <加入码>
/distantstock network leave
```

这些命令是**本地 Create 仓库 membership 的管理/兼容入口**，和便携终端 UI 里的“终端加入远仓网络”不是同一层。

命令会从玩家携带的便携终端中解析当前选中的**本地** Create 仓库：

- `network create`：创建正式远仓网络，并把当前本地 Create 仓库作为首个成员加入；
- `network join`：把当前本地 Create 仓库加入指定 Join Code 对应的远仓网络；
- `network leave`：把当前本地 Create 仓库从正式 membership 中移除；
- `network code / reset-code`：只有网络创建者在 authority 节点上可用。

玩家正常配置更推荐使用新版 UI：

```text
便携终端先创建 / 加入远仓网络
→ 到本地仓库
→ 用终端右键已绑定 Create 物流的远仓港
→ 把整张 Create 仓库加入该远仓网络
```

**注意：**便携终端界面里的“退出远仓网络”目前只清除这台终端自己的远仓网络上下文，不会自动把 Create 仓库 membership 一起删除。真正让本地 Create 仓库退网，使用管理命令或其它明确的 membership 管理入口。

### 接收港地址

```text
/distantstock group list
/distantstock group create <名称>
/distantstock group delete ...
/distantstock group member ...
```

### 远端记录

```text
/distantstock remote list
/distantstock remote forget ...
```

### 港口诊断

```text
/distantstock dock group ...
/distantstock dock send-to ...
```

命令的具体参数以游戏内命令补全为准。

## 退件箱

某些包裹无法正常返回原远仓港时，会进入服务器侧退件箱。

查看：

```text
/distantstock returns list
```

恢复方式包括：

```text
/distantstock returns restore <id>
/distantstock returns give <id>
/distantstock returns export <id>
```

- `restore`：尝试恢复到物流系统；
- `give`：交给管理员玩家；
- `export`：导出记录用于人工检查。

处理前建议先确认为什么包裹退回，避免刚恢复就再次进入相同故障。

---

## 隔离库

无法安全解码、存在不兼容内容或不能按正常流程交付的包裹会进入隔离库。

查看：

```text
/distantstock quarantine list
```

处理命令：

```text
/distantstock quarantine give <id>
/distantstock quarantine export <id>
/distantstock quarantine discard <id>
```

`discard` 是明确删除记录。不要把它当作清理警告的常规操作。

发生跨服 Mod 不一致、物品缺失或数据组件不兼容时，优先 `export` 检查。

## 包裹安全

远仓的跨服包裹不是“发一次消息然后来源删物品”。

当前实现包含：

- 持久 parcel ID；
- 来源托管记录；
- 目标幂等登记；
- 重复消息去重；
- 明确回执；
- 失败重试；
- 退件；
- 隔离；
- 原始数据与摘要保留。

交接遵循“新的唯一保管方确认写入以后，旧保管方才删除记录”的原则。

这也是为什么看到消息队列残留时，不应直接手工删除整个 `transerver/messages/` 目录。

## 升级

升级远仓前：

1. 完全关闭 Minecraft 服务器；
2. 备份世界；
3. 备份 Transerver 节点身份；
4. 备份 Distant Stock 数据；
5. 替换 JAR；
6. 启动 Router；
7. 再启动各 Minecraft 节点；
8. 用 `/transerver status` 和 `/distantstock status` 检查。

不要在服务器仍运行时覆盖 Mod JAR。

---

## 出现跨服故障时应该保留什么

如果需要提交问题，至少保留：

- 两端 `latest.log`；
- `/transerver status`；
- `/transerver identity`；
- `/distantstock status`；
- 相关日志台小票；
- 是否出现退件或隔离记录；
- 故障发生前后有没有重启、换世界或替换 Mod。

不要为了“让它重新试一次”先清消息目录、节点身份或退件记录。那些文件通常正是判断包裹最后落在哪一层的证据。
