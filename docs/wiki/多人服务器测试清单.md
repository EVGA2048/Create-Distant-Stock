# 多人服务器测试清单

这页用于开发服 / 公测服验收。

目标不是证明“点几下能跑”，而是证明：

- 不串仓；
- 不越权；
- 不公开无关玩家仓库；
- 不重复发货；
- 接收端消失时不吞包；
- 旧存档升级后身份不乱。

建议两台服务器、至少两名玩家测试。

---

## 0. 版本一致性

两端先确认：

- Minecraft 1.21.1；
- Create 6.0.10；
- Distant Stock Jar 一致；
- Transerver Jar 一致。

服务器完整重启后再测试 NodeIdentity，不要只 `/reload`。

---

## 1. 全新终端隐私测试

玩家 A 放一个全新便携终端。

预期：

- 可以进入远仓网络页面；
- 可以创建 / 输入 Join Code；
- **不能看到服务器其它玩家全部 Create 仓储网络列表**；
- 未加入正式远仓网络时，成员仓库列表为空。

如果这里出现一串陌生 Create UUID，直接判定失败。

---

## 2. 创建远仓网络

玩家 A 创建：

```text
Elysium-Test
```

预期：

- 获得 8 位 `XXXX-XXXX` 加入码；
- 终端进入该远仓网络；
- 此时仍可以没有任何成员仓库。

然后重开终端，状态必须保持。

---

## 3. 本地仓库收编

服务器 A 准备一张 Create 仓储网络 X，并让远仓港先绑定 X。

玩家 A 拿 `Elysium-Test` 终端普通右键港。

预期：

- X 成为远仓网络成员；
- 自动得到人类可读仓库名；
- 终端自动选中 X；
- 第二台同属 X 的远仓港不需要再创建另一份 membership。

---

## 4. 一张 Create 仓库不能加入两张远仓网络

再准备一台加入 `Other-Test` 的终端，尝试收编同一张 X。

预期：

- 被拒绝；
- 明确提示 X 已经属于另一张远仓网络；
- 原 membership 不被覆盖。

---

## 5. Create 管理权限测试

让玩家 B 不是 X 的 owner。

### X 未锁定

测试已有请求设备普通使用。

预期：如果 Create 允许普通 interaction，B 可以使用。

### B 尝试修改 membership

让 B 拿终端右键一个尚未入网的本地 Create 网络。

预期：没有 `mayAdministrate` 时拒绝。

### X 锁定

在请求台切换“阻止其他玩家从此处下单”。

预期：

- 非 owner 的 B 不能继续从 X 下单；
- A 仍可使用；
- 远端其它仓库不会因为这个动作被锁。

---

## 6. 跨服加入

服务器 B 用 A 的 Join Code 加入 `Elysium-Test`。

预期：

- 加入成功；
- B 的终端知道自己在 `Elysium-Test`；
- 服务器 B 尚未收编任何 Create 仓库时，成员列表至少能看到已经公布的 A 侧成员，但不会看到其它无关 Create 网络。

然后在 B 侧收编 Create 仓库 Y。

最终两端应该只看到：

```text
Elysium-Test
├─ A：X
└─ B：Y
```

---

## 7. 仓库名称测试

在 A 侧把 X 改名为：

```text
中央仓库
```

预期：

- 本机列表更新；
- 对端后续公告刷新后显示这个人类名称；
- 内部 RemoteNetworkId 不改变。

---

## 8. 仪表 A/B 入网测试

### 先测未调谐放置

拿一只全新的远仓仪表，不右键任何 Create 物流链接，直接放置。

预期：

- 可以正常放下；
- 不要求“先调谐再放置”；
- 此时本地 Create 库存网络为空；
- 即使随后配置了远仓来源，也不会因为本地网络未配置而自动疯狂下单。

再拿另一只远仓仪表，先调谐到本地 Create 网络 X，然后右键已经放置的仪表格。

预期：

- 已放置仪表获得本地 Create 网络 X；
- 手里的仪表不被消耗；
- 已经配置的正式远仓网络 / 来源仓库不被改掉。

### A：Join Code

新远仓仪表输入 Join Code。

预期：

- 仪表加入 `Elysium-Test`；
- 来源列表只有 X / Y 等成员仓库；
- 不显示其它玩家 Create 网络。

### B：终端配对

拿只加入 `Elysium-Test`、但没选仓库的终端右键新仪表。

预期：只复制远仓网络，来源保持未选。

再拿已经选中 X 的终端配对另一块仪表。

预期：远仓网络与来源仓库一起复制。

远仓红石请求器重复同样测试。

同时检查红石请求器：

- 接收港地址字段显示名称而不是 UUID 前 8 位；
- 点击字段能看到当前正式远仓网络中的接收港地址列表；
- 选中地址、保存、重开界面以后仍显示同一名称；
- 红石上升沿触发时有 Create 原版请求器的成功 / 失败动画；
- 配置完整时来源远仓确实收到订单并开始打包。

---

## 9. 第一笔跨服订单

用最简单物品：

```text
石头 × 1
```

A 为来源，B 为接收。

预期：

1. B 提交订单；
2. A Create 仓库实际打包；
3. 包裹进入 A 发送港；
4. A 在真正发送前探测 B 接收组；
5. 包裹跨服；
6. B 接收港得到包裹；
7. 本地物流取走。

最终总物品数不能增加或减少。

---

## 10. 无接收端安全测试

把 B 的接收港：

- 拆掉；或
- 切成只发送；或
- 塞满；或
- 让互通塔停止工作。

然后 A 再产生一个包裹。

预期：

- A 的包裹**留在发送港**；
- 不进入跨服 escrow；
- 不因为这次失败扣以太；
- 护目镜提示“目标接收港地址当前没有可用接收港”；
- 日志台记录 WARN；
- 不生成第二个“泛化卡包”重复告警。

恢复 B 接收端以后，A 应继续发送原来的那一个包裹。

---

## 11. 多接收港测试

在同一个接收港组挂两台以上可用港。

预期：

- 优先级高的可用港先被选择；
- 相同优先级之间轮流分担；
- 某台满以后其它有空间港仍能继续接收。

---

## 12. Transerver 断线测试

正常运行时临时让其中一端 transport 不可用。

预期：

- 本机 NodeIdentity 不消失；
- 已存在远仓网络上下文不因为 transport 断线变成“未配置节点”；
- 新的远程 Join Code 查询失败时给出明确 transport 提示；
- 已经在发送港等待的包裹不会凭空消失。

恢复 transport 后继续观察是否自动恢复。

---

## 13. 互通塔停机测试

运行中切断塔动力或制造应力过载。

预期：

- 塔停止带载；
- 覆盖内远仓设备显示未激活 / 塔停机；
- 接收港不再被对端算作可用 receiver；
- 修复动力后恢复。

---

## 14. 以太不足测试

如果启用了以太收费：

1. 把塔储罐耗空；
2. 让发送港产生待发包裹。

预期：

- 包裹保留；
- 港报告以太不足；
- 补充以太以后自动重试；
- 只在真正离开港时结算一次费用。

---

## 15. 日志台纸卷与状态码

全新日志台：

```text
0 / 16
PE
```

装入纸卷：

```text
16 / 16
OK
```

制造 WARN：预期 `AL`。

打印确认但不修故障：预期 `AC`。

制造 ERROR：预期 `ER`。

让绑定网络不可用：预期 `--`。

特别检查：0/16 时不能仍显示 `OK`。

---

## 16. 客户端重连 / 服务器重启

完整重启两端。

预期持久化：

- Transerver NodeIdentity；
- 远仓网络 UUID；
- Join Code；
- Create warehouse membership；
- 仓库显示名；
- 设备远仓网络上下文；
- 已选来源仓库；
- 接收港组；
- 等待中的安全包裹状态。

重启不能把一张 Create 仓库突然“变成另一张仓库”。

---

## 17. 旧客户端 / 版本不一致测试

公测时如果某玩家行为明显和其他人不同，第一件事先核 Jar hash。

不要在两边版本不一致时继续研究路由现象，因为 wire codec、节点发现和设备状态都有可能已经不同。

---

## 报 Bug 时最好一起提供

- 两端 Distant Stock / Transerver Jar SHA256；
- 哪台服务器、哪个玩家；
- 具体远仓网络名；
- 来源仓库和目标仓库显示名；
- 接收港组名；
- 发送港 / 接收港护目镜截图；
- 日志台状态码；
- `/distantstock status`；
- 问题发生前最后一个明确成功步骤；
- 服务端日志对应时间段。

这样基本能把“远仓玄学”压缩成一条可复现路径。
