# 常见问题与排障

这一页按**症状**排查。

如果系统完全不工作，不要同时重做两端配置。先找出问题停在哪一层：

```text
远仓网络身份
  ↓
Create 仓库 membership
  ↓
设备 / 港绑定
  ↓
互通塔带载
  ↓
来源端下单与打包
  ↓
发送港
  ↓
Transerver
  ↓
目标接收港组
  ↓
本地 Create 包裹物流
```

---

## 打开终端后一个仓库都没有

这在**全新终端**上是正常现象。

当前版本不会把全服扫描到的 Create 仓储网络公开给客户端。

正确流程：

1. 先在终端创建或加入正式远仓网络；
2. 拿终端去本地仓库；
3. 用终端右键一台已经绑定本地 Create 网络的远仓港；
4. 把这张 Create 仓库加入当前远仓网络；
5. 它才会出现在成员仓库列表中。

如果已经执行过第 4 步但仍看不到：

- 确认动作栏是否出现“已将这张 Create 仓储网络加入「…」”；
- 确认终端仍在同一张远仓网络；
- 用工程师护目镜确认港实际绑定的是预期 Create 网络；
- 管理员可用 `/distantstock stock` 与 `/distantstock network list` 辅助检查。

---

## 远仓港提示“还没有连接 Create 仓储网络”

远仓港在加入远仓网络前，必须先知道自己属于哪张本地 Create 物流网络。

做法：

1. 拿**远仓港物品**；
2. 右键目标 Create 物流链接；
3. 看到绑定成功提示后再放置远仓港；
4. 再拿已经加入远仓网络的便携终端右键它。

“港绑定 Create 网络”和“Create 仓库加入远仓网络”是两个独立步骤。

---

## 提示“你没有这张 Create 仓储网络的管理权限”

以下动作需要 Create 的**管理权限**：

- 把本地 Create 仓库第一次加入远仓网络；
- 修改本地仓库的远仓显示名；
- 切换请求台中 Create 原生物流网络锁定状态。

已经配置好的普通下单只要求 Create 的交互权限。

因此一个由其他玩家拥有、但没有锁定的 Create 网络，可能允许你正常使用已有设备，却不允许你改变它的远仓 membership。

---

## 提示“这张 Create 仓储网络已锁定，你没有操作权限”

这是 Create 原生物流网络权限在生效。

远仓没有绕过它。

请求台里的“阻止其他玩家从此处下单”实际操作的是 Create 自己的 `LogisticsNetwork.locked`。

如果你不是该网络 owner，网络锁定后无法再从它正常下单。

---

## 加入码一直搜不到

先区分两种情况。

### 加入码属于本机创建的远仓网络

不要求跨服 transport。服务端可以直接在本地网络目录中找到它。

### 加入码属于另一台服务器

要求 Transerver transport 实际在线。

如果看到：

```text
本存档没有这个加入码；当前未连接 Transerver，无法查询其它节点。
```

说明稳定 NodeIdentity 可能已经存在，但跨服 transport 没有工作。

检查：

- 两边 Transerver 版本是否一致；
- Router / secret / transport 配置；
- `/distantstock status`；
- 监视器的链路状态。

加入码输入允许省略 `-`，大小写不敏感，但必须实际包含 8 个字母或数字字符。

---

## 提示“Transerver 节点身份尚未加载”

当前架构中，**节点身份与 transport 是否在线已经分离**。

正常情况下，即使跨服 transport 暂时关闭，Transerver 也应该从：

```text
transerver/node-identity.properties
```

加载稳定节点 UUID，并向 Distant Stock 提供本机身份。

如果服务器完整启动后仍长期出现这条提示：

- 确认服务器装的是与当前 Distant Stock 配套的 Transerver；
- 检查 Transerver 是否真的被 NeoForge 加载；
- 检查 `node-identity.properties` 是否可读；
- 看启动日志中 Transerver lifecycle 是否报错。

不要通过手工伪造某个固定 UUID 来绕过。稳定 NodeIdentity 是正式路由身份。

---

## 仪表 / 红石请求器没有任何来源仓库可选

它们现在同样不会枚举全服 Create 网络。

先让设备获得远仓网络上下文：

- **A：**在设备 UI 输入 8 位加入码；
- **B：**拿已经加入远仓网络的便携终端右键设备。

然后来源列表才会显示该远仓网络的成员仓库。

如果用 B 方式时终端已经选中了成员仓库，设备会顺手复制该来源；如果终端只是加入网络但没有选仓库，则只完成远仓网络配对。

## 远仓港有包裹，但一直不发送

先戴工程师护目镜看原因。

### “目标接收港地址当前没有可用接收港”

发送端在真正交出包裹前会做一次**实时接收端探测**。

远端只有满足这些条件才算“可用接收港”：

- 港位于正确接收港组；
- 港处于可接收模式；
- 港没有满；
- 港实际已加载；
- 港在运行中的互通塔覆盖范围内。

远端回答不可用时：

- 包裹继续留在发送港；
- 不进入 Parcel Escrow；
- 不扣本次以太费用；
- 日志系统记录 `DOCK_NO_RECEIVER` WARN；
- 港显示明确的无接收端原因。

这不是丢包。

### 第一次显示“正在等接收端”，过一会变无接收端

远程 probe 第一次发出后会短暂等待回复。如果一整个 probe 窗口都没有得到有效答复，发送端会把目标视为当前不可用，同时后台继续重试。

这通常意味着：

- 对端 Transerver 不通；
- 对端接收港没有实际可用容量；
- 接收组或远仓网络作用域不一致。

---

## 接收港明明存在，为什么仍然算“没有可用接收港”

“方块存在”不等于“当前可收件”。

以下港不会计入可用接收端：

- 只发送模式；
- 已经满了；
- 不在运行中的互通塔覆盖范围；
- 区块没有实际加载；
- 接收港组不对。

多港系统会在同组中选择有空间的港。相同优先级的可用港会轮流承担流量。

---

## 包裹塞进港以后拿不出来

港内部区分：

- 收到的包裹；
- 正在等待发送的包裹；
- 已经确认走不通的 stranded 包裹；
- 回退缓存。

真正正在传输窗口中的包裹不能被玩家强行拿走，否则会破坏单一保管方原则。

但已经确认无法继续发送的 stranded 包裹，可以被玩家或下方自动化取回。

港底面同时向漏斗 / 溜槽暴露收到、stranded 与回退内容，方便自动化恢复。

---

## 互通塔看起来建好了，但设备还是“未激活”

先看护目镜。

最低要求：

- 底座；
- 至少 5 个连续耦合器；
- 顶部以太谐振器；
- 动力从底座**正下方**输入；
- 塔没有应力过载；
- 设备在塔的覆盖半径内；
- 带载设备数没有超过当前等级上限。

如果护目镜显示：

```text
互通塔未运行：动力不足或应力过载
```

优先检查旋转网络，而不是 Transerver。

如果设备提示：

```text
未激活：不在运行中的互通塔覆盖范围内
```

说明它不是“网络配置错了”，而是当前没有运行塔愿意带载这台设备。

---

## 互通塔有动力，但包裹提示没有以太

如果服务器启用了塔运输费用，真正离开受塔带载远仓港的包裹才会结算以太。

默认每个包裹：

```text
250 mB 以太凝液
```

底座储罐容量：

```text
4000 mB
```

没有以太时，港不会疯狂每 tick 重试，而会延迟后重新尝试。给塔补充以太后应能自动恢复发送。

---

## 日志台 0/16 为什么不是 OK

这是故意的。

新日志台没有纸时：

```text
PE
```

代表 `Paper Empty`。

当前状态码：

- `OK`：正常；
- `PE`：缺纸；
- `AL`：未确认 WARN；
- `ER`：未确认 ERROR；
- `AC`：已确认但故障仍未恢复；
- `--`：绑定网络不可用。

没有纸时无法打印，也就无法 ACK。

---

## 日志台打印以后为什么红/黄灯还没灭

因为：

```text
打印 = ACK
ACK ≠ 故障恢复
```

打印只表示“维护人员已经确认看到了这条告警”。如果真正故障仍然存在，日志台继续保持告警状态，只是不再针对已确认事件蜂鸣。

---

## 终端点“退出网络”以后，仓库怎么还在远仓网络里

因为当前 UI 的“退出网络”是**终端自身退出**：清掉这台终端携带的远仓 network context。

它不是“把整张 Create 仓库踢出 membership”。

管理员如果要让本地 Create 仓库真正退网，可使用：

```text
/distantstock network leave
```

这需要终端当前指向该本地 Create 仓库，并受现有 authority 约束。

---

## 换服务器 Jar 后旧仓库身份不对

当前版本使用 Transerver 持久化 NodeIdentity，并会按本地 Create frequency 迁移旧身份编码。

如果旧存档升级后某张仓库突然看不到原远仓 network membership：

1. 不要删除 `node-identity.properties`；
2. 不要重建整张远仓网络；
3. 先确认当前 Create frequency 仍然是原仓库；
4. 打开终端网络页或让 scanner 完成一次扫描；
5. 再检查 `distantstock_networks` SavedData 与服务器日志。

身份迁移应该折叠旧节点编码，而不是重新创造一个假“本机 UUID”。

---

## 最后还是不知道卡在哪

按这个顺序截信息最有用：

1. `/distantstock status`；
2. 监视器第一页和链路页；
3. 互通塔护目镜；
4. 发送端远仓港护目镜；
5. 接收端远仓港护目镜；
6. 日志台状态码和当前活动事件；
7. 来源 Create 仓库是否真的生成包裹；
8. 服务端最新相关日志。

比“它不动了”有用一百倍（笑）。
