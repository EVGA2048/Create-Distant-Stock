# 机械动力：远仓 Wiki

**机械动力：远仓（Create: Distant Stock）** 是围绕 Create 仓储物流扩展的一套跨服仓储与包裹路由系统。

它不会把两台服务器的库存合并成一个“无限远程箱子”。来源仓库仍然要真正接单、打包，包裹仍然要经过远仓港、Transerver 和接收端本地物流。

```text
来源 Create 仓储网络
    ↓
远仓打包机
    ↓
远仓港
    ↓
──────── Transerver ────────
    ↓
接收港组
    ↓
本地 Create 包裹物流
```

只想先让第一笔跨服订单跑起来，直接看：[快速开始](快速开始.md)。

---

## 先分清五个概念

### Create 仓储网络

Create 自己的物流网络。库存、仓储链接、本地地址和打包设备仍然都属于 Create。

远仓把一张 Create 仓储网络视作一座独立仓库。它不会改变 Create 自己的所有权与锁定规则。

### 远仓网络

远仓的**路由命名空间**，也是多张 Create 仓库之间的成员关系。

```text
远仓网络「Elysium」
├─ ES2：中央仓库
├─ Parallel：主工厂
└─ Test：测试仓库
```

同一张 Create 仓储网络同时只能属于一张正式远仓网络。

现在的正常流程是：**便携式远仓终端先创建或加入远仓网络，然后玩家亲自到本地仓库，用终端右键已经绑定 Create 物流的远仓港，把这张 Create 仓库收进该远仓网络。**

远仓不会把当前服务器上扫描到的所有 Create 网络直接发给客户端。一个终端只会看到它所在远仓网络已经登记的成员仓库。这个限制同时是交互设计和权限边界，不只是把列表“藏起来”。

### 加入码

正式远仓网络由创建者生成一个 **8 位 Join Code**，界面显示为：

```text
AB3D-7K2M
```

加入码不是远仓网络 UUID，也不是服务器节点 UUID。它只用于首次授权加入；设备和终端成功加入以后保存的是正式远仓网络身份。

重置加入码不会让已经加入的仓库或设备掉线。

### 接收港地址

一组接收远仓包裹的远仓港。

它回答：

> 这个跨服包裹应该从哪一组远仓港落地？

同一个地址可以有多个港。远仓会在组内寻找当前可接收的端口。

### 包裹地址

Create 包裹自身携带的地址。

两者的阶段不同：

```text
跨服阶段：接收港地址
落地以后：Create 包裹地址
```

例如远仓先把包裹送到接收港组 `Factory-A`，包裹从港出来后，再由本地 Create 物流按 `Gear-Line` 分拣。

## 一条推荐的配置顺序

```text
便携式远仓终端
  ↓
创建 / 输入加入码加入远仓网络
  ↓
拿终端到本地仓库
  ↓
右键已经绑定 Create 物流网络的远仓港
  ↓
Create 仓库成为该远仓网络的成员
  ↓
终端 / 请求台 / 仪表 / 红石请求器
只从这张远仓网络的成员仓库中选择货源
```

这套顺序解决了公共服务器最重要的问题：玩家不需要、也不应该浏览全服所有人的 Create 仓储网络。

## 远仓的基本原则

- 每张 Create 仓储网络仍然独立存在；
- 跨服订单必须由来源仓库真实打包；
- 包裹必须经过远仓港；
- 一张 Create 仓库只能属于一张正式远仓网络；
- 客户端只获得当前远仓网络内的成员仓库目录；
- 本地 Create 网络的交互与管理权限继续沿用 Create 自己的权限模型；
- 发送、接收、退件和隔离都有持久状态；
- 一个包裹在交接过程中只允许有一个明确的保管方；
- 目标拒收、断线或区块卸载时优先保住物品，而不是强行完成运输；
- 远仓设备由互通塔提供工作范围和带载能力；
- Transerver 负责服务器之间的可靠消息，游戏内机器不保存其它服务器的 IP 或端口。
