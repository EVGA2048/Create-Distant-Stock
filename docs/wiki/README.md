# 机械动力：远仓 Wiki

**机械动力：远仓（Create: Distant Stock）** 是一个围绕 Create 仓储物流扩展的附属模组。

它做的事情很具体：让一张 Create 仓储网络可以被另一台服务器看见、下单，并把最终生成的包裹可靠地送到另一端。

远仓不会把两边的仓库合并成一个无限大的库存，也不会让物品凭空出现在另一台服务器。跨服运输仍然经过订单、打包、路由、远仓港和本地物流。

```text
服务器 A
Create 仓储网络
    ↓
远仓打包机
    ↓
远仓港
    ↓
──────── Transerver ────────
    ↓
远仓港
    ↓
本地包裹物流
    ↓
服务器 B
```

如果只想先把系统跑起来，直接看：[快速开始](快速开始.md)。

## 先分清四个名字

远仓里最容易混淆的不是机器，而是“网络”和“地址”。下面四个词不是同一件东西。

### Create 仓储网络

Create 自己的物流网络。

它拥有库存、仓储链接、打包设备和本地地址。远仓读取的“仓库里有什么”，说的就是这张网络。

一台服务器可以同时有很多张 Create 仓储网络。

### 远仓网络

远仓的**路由命名空间**，同时也是多张 Create 仓储网络之间的成员关系。

例如：

```text
远仓网络「Elysium」
├─ ES2：中央仓库
├─ Parallel：工业仓库
└─ Test：测试仓库
```

加入同一个远仓网络，并不代表三张库存合并了。它表示这些仓储网络可以互相发现，并且它们的接收港地址、订单和运输都在同一个命名空间内。

**远仓运输必须属于一个正式远仓网络。** 未创建或未加入远仓网络的 Create 仓储网络仍可在本地终端中查看，但不能继续使用远仓地址、远程订单或远仓设备绑定。不同远仓网络可以拥有相同名称的接收港地址，例如两张网络都可以各自存在一个 `333`，二者互不相认。

创建远仓网络的一方会得到一个长期加入码。其它服务器使用这个加入码加入。

### 接收港地址

一组远仓港的逻辑名称。

它回答的是：

> **这个跨服包裹应该从哪一组远仓港出来？**

同一个接收港地址可以挂多个远仓港。包裹抵达时，系统会在这组港里选择可用的接收端，而不是把一个地址死绑到一个方块坐标上。

### 包裹地址

Create 包裹自身携带的本地地址。

它回答的是：

> **包裹已经从远仓港出来以后，本地物流还要把它送到哪里？**

所以完整路线通常是：

```text
远端仓库
  ↓
接收港地址：Factory-A
  ↓
远仓港组
  ↓
包裹地址：Line-03
  ↓
本地 Create 包裹物流
```

**接收港地址负责跨服落点；包裹地址负责落地后的本地分拣。**

## 远仓的基本原则

远仓的实现更接近物流系统，而不是“跨服传送指令”。

- 每张 Create 仓储网络仍然独立存在；
- 跨服订单仍然要由来源仓库实际打包；
- 包裹必须经过远仓港；
- 发送、接收、退件和隔离都有持久状态；
- 一个包裹在交接过程中只允许有一个明确的保管方；
- 目标拒收、断线或区块卸载时优先保住物品，而不是强行完成运输；
- 远仓设备由互通塔提供工作范围和带载能力；
- Transerver 负责服务器之间的可靠消息，不由游戏里的机器保存 IP 或端口。
